# Editar Produtos da Loja

> Muda o catálogo inteiro de uma vez: preço, marca, tags, status, tamanhos, cores e política de estoque, sempre com cópia de segurança antes, plano aprovado por você no meio e conferência depois.

## O que você precisa ter antes

- Shopify CLI instalado: `npm i -g @shopify/cli`.
- Sua loja autenticada na CLI, com os escopos de produto, arquivo, estoque e navegação (o comando está logo abaixo).
- Uma pasta no seu computador para guardar a cópia do catálogo antes da edição.
- Se a mudança mexe em preço: o custo de cada produto em dólar. Não é preciso somar frete, ele já está dentro desse custo.
- Nada de Node, Python ou script extra: esta skill trabalha só com a CLI da Shopify.

```bash
shopify store auth --store sualoja.myshopify.com \
  --scopes "read_products,write_products,read_files,write_files,read_inventory,write_inventory,read_online_store_navigation,write_online_store_navigation"
```

O escopo de navegação é o que permite criar o redirecionamento 301 quando um endereço de produto muda. Sem ele, o link antigo vira 404.

## O que ela faz

Cobre as edições mecânicas do catálogo, aquelas em que a decisão é uma regra e não uma escrita nova:

| Você pede | O que acontece no catálogo |
|---|---|
| "divide o preço por 5 com 60% de desconto" | Preço novo arredondado e riscado recalculado em cima do preço novo |
| "põe tudo a 89,90" ou "sobe 10%" | Preço fixo ou aumento percentual em todas as variantes |
| "troca a marca antiga pela nova" | Substituição em título, fornecedor, tipo de produto, descrição, SEO e endereço do produto |
| "adiciona a tag promo" | Tags entram ou saem em lote |
| "ativa os produtos" | Status vai para ativo ou rascunho |
| "P, M, G para S, M, L" | Rótulos e valores de opção reescritos |
| "continua vendendo esgotado" | Toda variante fica com política de estoque CONTINUE |
| "limpa as coleções vazias" | Coleção sem produto é apagada |

Duas regras valem em toda operação:

1. **Produto sai sempre em "continuar vendendo sem estoque".** Ruptura curta de fornecedor é comum, e travar a venda por três dias significa perder o pedido depois de já ter pago pelo clique.
2. **Se o título ou a marca mudou, o endereço do produto muda junto, com redirecionamento 301 criado na mesma operação.** Endereço em português numa loja em inglês, ou com a marca antiga, fica lá para sempre e aparece no Google, no sitemap e nos seus anúncios.

O que ela não faz, e para onde manda:

| Pedido | Vai para |
|---|---|
| Traduzir o catálogo para outro idioma | [[05. Traduzir os Produtos]] |
| Escrever meta title, descrição e tags de SEO | [[06. Gerar SEO dos Produtos]] |
| Preencher os campos que o Google Shopping exige | [[47. Preparar Produtos para o Google]] |
| Converter as imagens antes de subir | [[15. Converter Imagens para WebP]] |

Se o seu pedido couber em duas dessas, a skill pergunta qual você quer antes de mexer em qualquer coisa.

## Como usar

### Passo 1: diga a loja e a mudança

Um exemplo do que basta: "na sualoja.myshopify.com, divide o preço por 5 com 60% de riscado e deixa tudo vendendo sem estoque".

### Passo 2: conferência de acesso

```bash
shopify store execute --store sualoja.myshopify.com --json \
  --query 'query { shop { name } products(first: 1) { nodes { id } } }'
```

Se isso não responder, o token expirou e o passo anterior de autenticação precisa ser refeito.

### Passo 3: cópia de segurança do catálogo

O catálogo inteiro vai para um arquivo local antes de qualquer escrita. É essa cópia que permite voltar atrás.

```bash
shopify store execute --store sualoja.myshopify.com --json \
  --query 'query { products(first: 25) {
    pageInfo { hasNextPage endCursor }
    nodes { id handle title vendor productType tags status descriptionHtml
            seo { title description }
            options { name optionValues { name } }
            variants(first: 30) { nodes { id title price compareAtPrice inventoryPolicy } } } } }' \
  > catalogo-antes-01.json
```

Vinte e cinco produtos por vez não é timidez. A Shopify recusa qualquer consulta que passe de 1.000 pontos, ela calcula esse custo antes de rodar e multiplica a lista de dentro pela de fora: 250 produtos com 100 variantes cada dá vinte e cinco mil nós e volta erro em vez de catálogo.

Repita a consulta trocando `products(first: 25)` por `products(first: 25, after: "<endCursor da página anterior>")` até `hasNextPage` vir `false`, gravando uma página por arquivo. Se algum produto seu passar de 30 variantes, suba o `variants` e baixe o `products` na mesma proporção.

### Passo 4: plano antes de escrever

A skill monta a lista completa do que muda e mostra três produtos com antes e depois lado a lado. Nada é escrito até você aprovar.

Preço, quando a operação é divisão:

```
preço novo   = arredonda para baixo em múltiplo de 0,10 (original / fator)
preço riscado = arredonda para cima em múltiplo de 0,10 (preço novo / (1 - desconto))

fator 5, desconto 60%:
  149,90 / 5 = 29,98  ->  29,90
  29,90 / 0,40 = 74,75 -> 74,80
  desconto real: (74,80 - 29,90) / 74,80 = 60,0%
```

Endereço do produto, quando o título muda: tudo em minúsculas, sem acento, sem ® e sem ™, qualquer caractere que não seja letra ou número vira hífen, hífens repetidos viram um só, e as pontas ficam sem hífen. Se dois produtos gerarem o mesmo endereço, o segundo ganha o sufixo `-2`.

### Passo 5: aplicar em lotes

Escrita não roda igual leitura. A CLI desliga mutation por padrão e responde que ela está desabilitada se você não passar `--allow-mutations`. E os valores não entram no meio do texto: eles vão num arquivo JSON à parte, apontado por `--variable-file` (no singular, sem "s"). O molde é sempre este:

```bash
shopify store execute --store sualoja.myshopify.com --json --allow-mutations \
  --query-file mutation.graphql --variable-file vars.json
```

Campos do produto. Em `mutation.graphql`:

```graphql
mutation($p: ProductUpdateInput!) {
  productUpdate(product: $p) { product { id handle } userErrors { field message } }
}
```

E em `vars.json`, um produto por chamada:

```json
{ "p": { "id": "gid://shopify/Product/123", "title": "Titulo novo", "handle": "titulo-novo", "vendor": "Marca Nova" } }
```

Preço e política de estoque, por variante. Em `mutation.graphql`:

```graphql
mutation($productId: ID!, $variants: [ProductVariantsBulkInput!]!) {
  productVariantsBulkUpdate(productId: $productId, variants: $variants) {
    userErrors { field message }
  }
}
```

E em `vars.json`, com `id`, `price`, `compareAtPrice` e `inventoryPolicy: CONTINUE` em cada variante:

```json
{ "productId": "gid://shopify/Product/123",
  "variants": [ { "id": "gid://shopify/ProductVariant/456", "price": "29.90", "compareAtPrice": "74.80", "inventoryPolicy": "CONTINUE" } ] }
```

Redirecionamento, sempre junto da troca de endereço. Esta não tem variável, mas continua precisando de `--allow-mutations`:

```bash
shopify store execute --store sualoja.myshopify.com --json --allow-mutations \
  --query 'mutation {
    urlRedirectCreate(urlRedirect: { path: "/products/endereco-antigo", target: "/products/endereco-novo" }) {
      userErrors { field message }
    }
  }'
```

### Passo 6: conferência final

O catálogo é lido de novo, depois da escrita, e a skill só dá a operação por encerrada com:

- zero endereço de produto com termo do idioma antigo ou da marca antiga;
- zero variante com política DENY;
- cada endereço trocado com o 301 correspondente respondendo;
- a lista de falhas, quando houver, com o motivo de cada uma.

## O que ela devolve

- O catálogo alterado na sua loja.
- `catalogo-antes-01.json` e seguintes, uma por página lida, a cópia de segurança para voltar atrás.
- Um resumo com quantos produtos mudaram, por campo, e quantas variantes ficaram em CONTINUE.
- A tabela dos endereços trocados, com o 301 de cada um.
- A lista dos produtos que falharam, com a mensagem de erro da Shopify.

## Onde erra

**Trocar o endereço e não criar o 301.** Pela API, `productUpdate` mudando o `handle` não cria redirecionamento nenhum: a Shopify só faz isso sozinha quando você renomeia pelo painel com a caixinha marcada. O link antigo, que já está em anúncio, e-mail e no Google, passa a devolver 404. Como perceber: abra o endereço antigo numa janela anônima; se der 404, o redirecionamento não existe.

**Trocar a marca só no título.** O nome antigo continua no fornecedor, no tipo de produto, no meta title e no meio da descrição, e volta a aparecer no Google semanas depois. Antes de encerrar, procure o termo antigo em todos os campos, não só no título.

**A marca antiga escrita com maiúscula escapando da troca.** Uma substituição que não ignora maiúsculas e minúsculas deixa passar a grafia com inicial maiúscula. Confira procurando o termo em minúsculas e com inicial maiúscula.

**Dividir o preço duas vezes.** A segunda passada divide o preço já dividido, e o riscado fica com um desconto impossível. Compare com a cópia de segurança antes de repetir a operação.

**Alt text aplicado antes de trocar as imagens.** A troca sobe arquivos novos, e o alt volta a ficar vazio. A ordem é imagem primeiro, alt text depois.

**Dois produtos com o mesmo título.** Os dois geram o mesmo endereço e a segunda escrita falha com erro de handle duplicado. O sufixo `-2` resolve, mas ele precisa estar no plano, não descoberto no meio da execução.

**A saída da CLI não é JSON puro.** O comando imprime uma linha de cabeçalho antes do JSON, e quem tenta ler o arquivo direto recebe erro de parse. Corte tudo que vem antes da primeira chave `{`.

**Passar tudo para rascunho de uma vez.** As coleções da home ficam vazias e a loja parece quebrada para quem estiver navegando naquele momento. Mudança de status em massa se faz com a loja fora do ar ou fora do horário de tráfego.
