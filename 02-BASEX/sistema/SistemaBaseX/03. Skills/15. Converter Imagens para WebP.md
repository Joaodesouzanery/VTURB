## Contexto

Converte imagens (PNG, JPG, JPEG, TIFF, HEIC, BMP, GIF) para WebP usando Pillow (PIL) em Python. Funciona com arquivo unico ou pasta inteira. Mostra tabela de reducao de tamanho ao final.

WebP entrega 25-90% menos peso que PNG/JPG mantendo qualidade visual indistinguivel para a maioria dos usos web. Ideal para: assets de loja Shopify, banners, capas de produto, imagens de blog, hero images.

Usar quando:
- "converte essa pasta de imagens pra webp"
- "comprime essas imagens"
- "transforma esses PNGs em WebP"
- "otimiza essas imagens pra web"
- Subir imagens em loja Shopify (queryload menor)
- Reduzir tamanho de assets de uma apresentacao ou landing

### Opcionais (perguntar so se contexto ambiguo)
- **Qualidade?** (default: 80). Use 75-85 para web normal, 90+ para fotografia de produto, 60-70 para thumbnails.
- **Lossless?** (default: false). True para logos, ilustracoes vetoriais rasterizadas, screenshots onde nao pode ter qualquer perda.
- **Substituir originais?** (default: false, mantem). True so se o usuario confirmar que tem backup.
- **Recursivo?** (default: false). True para pastas com subpastas (assets/banners/, assets/produtos/, etc.).
- **Pasta de saida?** (default: mesma pasta). Util quando quer separar os originais dos otimizados.

## Pre-flight v2 (OBRIGATÓRIO)

```bash
PASTA_OU_ARQUIVO="{input}"

# 1. Path existe?
[ -e "$PASTA_OU_ARQUIVO" ] || { echo "FAIL: $PASTA_OU_ARQUIVO nao existe"; exit 1; }

# 2. Engine existe? (gate 14 da meta-task v2)
ARQUIVO="${BASEX_ARQUIVO:-$(cd "$(dirname "${BASH_SOURCE[0]:-.}")" && pwd)}"
ENGINE="$ARQUIVO/_engine/imagens-webp/convert.py"
# se nao achou, procurar a partir da pasta atual
[ -f "$ENGINE" ] || ENGINE="$(find "$HOME" -maxdepth 5 -path "*/SistemaBaseX/_engine/imagens-webp/convert.py" 2>/dev/null | head -1)"
[ -f "$ENGINE" ] || { echo "FAIL: engine $ENGINE nao existe"; exit 1; }

# 3. (o engine usa Pillow, nao precisa do binario cwebp — check removido)

# 4. Python 3+ + Pillow?
python3 -c "from PIL import Image" 2>/dev/null || { echo "FAIL: Pillow nao instalado. Rode: pip3 install --user Pillow"; exit 1; }

# 5. Contar arquivos a converter (.jpg, .jpeg, .png) — pre-view do escopo
if [ -d "$PASTA_OU_ARQUIVO" ]; then
  TOTAL=$(find "$PASTA_OU_ARQUIVO" -type f \( -iname "*.jpg" -o -iname "*.jpeg" -o -iname "*.png" \) | wc -l)
  TAMANHO_MB=$(du -sm "$PASTA_OU_ARQUIVO" | cut -f1)
  echo "Escopo: $TOTAL arquivos, ${TAMANHO_MB}MB"
fi

echo "OK pre-flight passou."
```

**Dry-run** (gate 16 da meta-task v2):

```bash
python3 _engine/imagens-webp/convert.py "$PASTA_OU_ARQUIVO" --dry-run
```

Mostra:
- Quantos arquivos seriam convertidos
- Tamanho original total vs estimativa pós-WebP (em geral -30% a -70%)
- Lista de arquivos a converter (sample 10)
- Se input é pasta com subpastas, mostra recursive on/off

NÃO toca em nenhum arquivo em modo dry-run.

**Rollback** (gate 17):

### Rede de segurança embutida

Nem toda imagem fica menor em WebP. Foto com muito ruído, textura fina ou já bem comprimida pode sair **maior**. Quando isso acontece, a engine descarta o `.webp`, mantém o original e escreve `mantido` na tabela. Sob `--replace`, essa imagem **não é apagada**. Sem essa trava, converter com `--replace` trocaria um arquivo menor por um maior e apagaria o bom.

Os arquivos originais .jpg/.png NÃO são deletados por default (o convert.py mantém os dois e gera só `.webp` novo). Se quiser deletar os originais depois de converter, usar `--replace`, e SEMPRE rodar com `--dry-run` antes para ver o que seria apagado.

Se quiser **reverter** WebP (deletar todos os `.webp` gerados):
```bash
find "$PASTA_OU_ARQUIVO" -type f -name "*.webp" -newer /tmp/marker-pre-webp -delete
```

(criar `touch /tmp/marker-pre-webp` ANTES de rodar conversão pra delimitar)

## Troubleshooting

| Erro | Causa | Solucao |
|------|-------|---------|
| `ERRO: Pillow nao esta instalado` | PIL nao disponivel no Python do sistema | Rodar `pip3 install --user Pillow` |
| `FALHA: ... cannot identify image file` | Arquivo corrompido ou nao e imagem real | Pular esse arquivo, listar pro usuario |
| `FALHA: ... HEIC ...` | Pillow sem suporte HEIC | Instalar `pip3 install --user pillow-heif` ou converter HEIC pra PNG antes |
| Conversao gera arquivo MAIOR que original | Imagem ja muito otimizada ou tem muito ruido | Avisar usuario, sugerir `--lossless` ou manter original |
| Nenhuma imagem encontrada | Path errado ou extensao nao suportada | Validar path; suportadas: png jpg jpeg tiff heic bmp gif |
| Permissao negada ao deletar original | `--replace` em pasta protegida | Tirar `--replace` ou rodar com permissao adequada |

## Notas adicionais

### Quando WebP NAO e a melhor escolha
- Imagens que precisam ser editadas frequentemente (manter PNG)
- Assets impressos (manter formato vetorial ou TIFF)
- Plataformas que nao suportam WebP (raras em 2026, mas e-mail clients antigos podem ter problema)

### Quality recomendada por uso

| Uso | Quality | Notas |
|-----|---------|-------|
| Hero/banner Shopify | 85 | Visual de impacto |
| Foto de produto | 90 | Detalhe importa |
| Thumbnail / preview | 65-70 | Tamanho prioritario |
| Background blur | 50 | Imperceptivel apos blur |
| Logo/icone | lossless | Sem perda |
| Blog post inline | 75-80 | Equilibrio padrao |

### Suporte HEIC

O Pillow nativo nao processa HEIC sem o plugin `pillow-heif`. Se o usuario tiver fotos do iPhone (.heic), instalar:

```bash
pip3 install --user pillow-heif
```

E adicionar no topo do script:
```python
from pillow_heif import register_heif_opener
register_heif_opener()
```
