# Patches Pixel-Perfect Dawn

Catálogo de patches/regras aprendidas em campo durante clonagens de loja Shopify Dawn. Extraído da skill de clonagem de tema em 2026-05-10.

> **Por que isso existe:** Dawn é um tema vanilla que dá conta de 60-70% do visual de uma loja premium, mas o salto pra 100% pixel-perfect exige patches recorrentes. Toda regra abaixo veio de retrabalho real numa operação (LF / Lucky Fours quando explicitada). Aplicar essas regras no Passo 14 da skill 02b. Aplicar Identidade no Tema Dawn economiza horas e evita ciclos de "parece igual mas tem algo errado".

> **Nota sobre numeração:** as R-regras preservam o range histórico R1-R47 com **gap em R27** (saltou na origem). Mantido pra rastreabilidade. R47 (validação pixel-perfect via `getComputedStyle`) NÃO está aqui — virou core da skill [[08. QA Visual da Loja]].

## Como usar este catálogo

1. Durante o Passo 14 de 02b. Aplicar Identidade no Tema Dawn (CSS customizado), abrir este doc lado a lado
2. Identificar quais áreas da referência batem com algum patch listado abaixo
3. Aplicar literalmente o CSS/JS/Liquid do patch — os valores são pixel-exatos pra Dawn ≥ v15
4. Validar visualmente após cada batch via [[08. QA Visual da Loja]]
5. Quando descobrir patch novo numa operação, adicionar aqui (próximo número livre — não reciclar R27)

## CSS Estrutural (transversal)

### R12. CSS: usar seletores por COMPONENTE, não globais

Cada componente pode ter fonte/cor diferente. Estrutura obrigatória do `custom.css`:
- `.header__heading-link` → fonte do logo
- `.header__menu-item` → fonte do menu (pode ser DIFERENTE do body!)
- `.announcement-bar__message` → fonte do announcement
- `h2, .title` → fonte dos títulos de seção
- `.card__heading a` → fonte do título do produto no card
- `.price-item--sale` → cor do preço de venda
- `.price-item--regular` → cor do preço riscado
- `.button` → cor e estilo do botão

NUNCA aplicar uma fonte global a tudo e assumir que está correto. Esta regra é a base estrutural do Passo 14 de 02b. Aplicar Identidade no Tema Dawn — ela ordena toda a tipografia.

## Header & Hero

### R1. image_height SEMPRE "adapt" no hero banner

NUNCA usar "large", "medium" ou "small" no image-banner do hero. Esses valores cortam a imagem. Usar `"image_height": "adapt"` pra respeitar a proporção natural da imagem e mostrar o conteúdo completo (textos embutidos na imagem não ficam cortados).

### R2. Announcement bar e header podem ter cores DIFERENTES

Extrair a cor de fundo de CADA UM separadamente. Erro comum: assumir que ambos são dark green. Na prática, muitos sites têm announcement bar CLARO (scheme-1) com header ESCURO (scheme-3). Verificar com JavaScript:

```javascript
// No Playwright, extrair cores separadamente
const annBar = document.querySelector('[class*="announcement"]');
const header = document.querySelector('header, [class*="header"]');
return {
  announcementBg: getComputedStyle(annBar).backgroundColor,
  headerBg: getComputedStyle(header).backgroundColor
};
```

### R13. Tema base pode ter brand text HARDCODED em header.liquid

Quando puxar um tema unpublished que ja foi customizado pra outra marca, SEMPRE buscar texto da marca anterior em `sections/header.liquid` (linhas 175 e 218 tipicamente, dentro de `<span class="h2">`). Search & replace pelo nome da marca alvo. Sem isso, o logo aparece com a marca antiga mesmo depois de atualizar settings.

### R14. NUNCA usar seletor `.gradient` para body bg

O footer e outras seções do Dawn tem classe `gradient` aplicada pelo color scheme. Se voce escrever `body, .gradient { background: #X !important }`, sobrescreve o scheme-3 do footer e ele perde a cor dark green. Use APENAS `body { background: #X !important }`.

### R22. Hero pill icon: SVG inline data-uri, nao emoji

Emoji ⏰ renderiza diferente em macOS vs Windows vs Linux. Pra icone consistente, use SVG inline como background-image:

```css
.lf-hero-cta::before {
  content:'';
  display:inline-block;
  width:16px; height:16px;
  background:url("data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 24 24' fill='none' stroke='white' stroke-width='2'><circle cx='12' cy='12' r='10'/><polyline points='12 6 12 12 16 14'/></svg>") center/contain no-repeat;
}
```

### R25. Icones do header: SEMPRE comparar SVG da referencia vs Dawn padrao

Dawn vem com 3 icones do header (search/account/cart) FILLED em viewBox 18x19 ou 40x40. Sites premium tipicamente customizam pelo menos o cart para um shape OUTLINED (shopping bag desenhada a mao). Workflow:

1. Inspecionar referencia: `document.querySelector('a[href*="cart"] svg')` retorna o SVG completo
2. Comparar com `assets/icon-cart-empty.svg` e `assets/icon-cart.svg` do Dawn
3. Se diferentes (viewBox, fill vs stroke, paths), substituir os 2 arquivos SVG do Dawn pelo conteudo da referencia
4. Adicionar CSS pra corrigir tamanho:

```css
.header__icon .icon-cart, .header__icon .icon-cart-empty { width: 24px !important; height: 28px !important; }
.header__icon-search .icon-search { width: 22px !important; height: 22px !important; }
.header__icon .icon-account { width: 22px !important; height: 23px !important; }
```

**Search** e **Account** geralmente sao iguais ao Dawn (filled magnifying glass / filled person silhouette). Mas SEMPRE verificar - alguns sites usam outline pra todos.

### R26. Header transparente over hero (template-index)

Sites premium tipicamente tem header TRANSPARENTE sobre o hero da home (overlay), e SOLIDO em outras paginas. LF faz isso: home tem hero preto com header transparente flutuando, collection/product/cart tem header dark green solido.

**Detectar:** Inspecionar `header-wrapper` na home da referencia: se `getComputedStyle(hw).backgroundColor === 'rgba(0, 0, 0, 0)'` → eh transparente.

**Implementar (3 etapas obrigatorias):**

1. Editar `layout/theme.liquid` para adicionar `template-{{ template.name }}` no body class:

```liquid
<body class="gradient template-{{ template.name }}{% if settings.animations_hover_elements != 'none' %} animate--hover-{{ settings.animations_hover_elements }}{% endif %}">
```

Dawn vanilla NAO adiciona o template class por padrao. Sem isso, qualquer CSS que dependa de `body.template-index` nao aplica.

2. Atualizar `assets/custom.css` com regra dual:

```css
/* Default: solid dark green em todas as paginas */
.header-wrapper, sticky-header.header-wrapper {
  background-color: #2C403C !important;
  border-bottom: none !important;
}
.header { background-color: transparent !important; }

/* Home: transparent overlay sobre hero */
body.template-index .header-wrapper,
body.template-index sticky-header.header-wrapper {
  background-color: transparent !important;
  position: absolute !important;
  top: var(--lf-ann-height, 41px) !important;
  left: 0 !important;
  right: 0 !important;
  z-index: 100 !important;
  width: 100% !important;
}

/* Sticky header (scrolled) volta a solido */
body.template-index .shopify-section-header-sticky .header-wrapper {
  position: fixed !important;
  top: 0 !important;
  background-color: #2C403C !important;
}

/* Hero precisa estender ate o topo (sob o header) */
body.template-index main > .shopify-section:first-child {
  margin-top: 0 !important;
  position: relative;
  z-index: 1;
}
```

3. Validar no browser DEPOIS de pushar:
- Home: header transparente, hero preto subindo ate logo abaixo da announcement bar
- Collection/product/cart: header dark green solido sobre conteudo light

**ERRO COMUM:** Esquecer o passo 1 (adicionar template class no body). Resultado: CSS nao aplica e header continua dark green em todas paginas.

### R28. Hero atualizado da referencia (mudanças frequentes)

Sites premium tipicamente tem uma seção de 4-6 cards lifestyle (foto + nome da coleção overlay) logo após o hero. As imagens da referência geralmente JÁ tem o texto baked ("MEN'S WATCHES" branco centralizado embedded no JPEG/WEBP).

**ERRO COMUM:** Adicionar tambem texto via CSS overlay → texto duplicado (uma vez baked, uma vez via CSS).

**Detectar:** Inspecionar `document.querySelector('.lf-clist a img').src` - se o image src é tipo `cdn/shop/collections/2_2.webp` da referencia, eh imagem com texto baked.

**Implementar custom-liquid LIMPO (sem .lbl overlay):**

```html
<style>.lf-clist{display:grid;grid-template-columns:repeat(5,1fr);gap:0;width:100%;background:#fff}.lf-clist a{position:relative;display:block;overflow:hidden;text-decoration:none;aspect-ratio:1/1;line-height:0}.lf-clist a img{width:100%;height:100%;object-fit:cover;display:block;transition:transform .5s ease}.lf-clist a:hover img{transform:scale(1.05)}@media(max-width:989px){.lf-clist{grid-template-columns:repeat(2,1fr)}}@media(max-width:489px){.lf-clist{grid-template-columns:1fr}}</style>
<div class="lf-clist">
  <a href="/collections/<handle>" aria-label="Men's Watches">
    <img src="<URL CDN da referencia>" alt="Men's Watches" loading="eager">
  </a>
  <!-- repetir para 5 cards -->
</div>
```

Apenas a imagem (com texto baked) + link clickavel + hover effect zoom. Sem texto adicional via CSS.

Sites premium fazem A/B test e atualizam o hero frequentemente. SEMPRE re-inspecionar a referência ao final da execução pra garantir que o hero/seções continuam matching. Mudanças tipicas:
- Title case (UPPERCASE → mixed case → bold parts)
- Subtitle adicionada/removida
- CTA color change (gold #cda51f, red #a32426, dark green)
- Trust signals: stars + customer count link

Workflow: re-rodar `inspect heroTitle/heroCTA/heroBgImg` no Playwright apos terminar tudo. Se mudou, atualizar custom-liquid.

## Featured & Collection cards

### R3. Featured collection: SEMPRE `full_width: true` + `page_width: 1600`

Sites premium usam o conteúdo quase edge-to-edge. O Dawn com page_width 1200 fica com margens excessivas. Setar `page_width: 1600` no settings_data.json e `full_width: true` em cada featured-collection.

### R5. Títulos de seção e cards de produto: CENTRALIZAR

Na maioria dos sites premium, "MEN'S BELTS", nomes de produto e preços são centralizados. Adicionar no CSS:

```css
.section-header__title, .title { text-align: center !important; }
.card-information, .card__content { text-align: center !important; }
```

### R29. Featured collection: detectar layout (slider 3-col vs grid vertical 4-col)

Sites premium tem DOIS padrões diferentes pra featured-collection:

**Padrao 1 - Best-Sellers / Hero collection** (mostra muitos produtos, scroll vertical):
- 4-col desktop, sem slider (`enable_desktop_slider: false`)
- 24-32 produtos visiveis (`products_to_show: 32`)
- Altura tipica 3000-4500px
- Posicionado logo apos collection-list lifestyle

**Padrao 2 - Curated collection** (Caspian, Calista, etc - mostra subset com slider):
- 3-col desktop com slider (`columns_desktop: 3, enable_desktop_slider: true`)
- 12-25 produtos no source mas slider mostra 3 por vez
- Altura tipica 800-870px
- Padrao alternado com image_banner entre eles

**Como detectar:** inspecionar `gridClass` da grid wrapper:
- `grid--4-col-desktop` + sem slider = Padrão 1 (Best-Sellers)
- `grid--3-col-desktop` + `slider` class = Padrão 2 (Curated)

**Erro comum:** colocar TODOS featured-collections como 4-col carousel. LF usa 4-col só pro Best-Sellers, 3-col pros demais.

### R30. Product card pixel-perfect: 7 detalhes que sites premium customizam

Dawn vanilla product card NAO bate com sites premium tipo LF. Sempre ajustar:

| Aspecto | Dawn padrao | LF (referencia premium) | CSS pra match |
|---|---|---|---|
| Title size | 14-18px | 23.4px Playfair | `font-size: 23.4px !important; letter-spacing: 0.78px !important` |
| Price size/weight | 14px / 400 | 13px / **700** Poppins | `font-size: 13px; font-weight: 700` em `.price-item--sale` |
| Compare-at color | rgba(33,33,33,0.5) lighter | rgba(33,33,33,0.9) **same as sale** | `.price-item--regular { color: rgba(33,33,33,0.9) !important }` |
| Card border-radius | 12px (todos os 4 cantos) | **12px 12px 0 0** (so topo) | `.card .card__media { border-radius: 12px 12px 0 0 !important; overflow: hidden !important }` |
| Badge text | "Sale" | "BEST SELLER" (custom) | Editar `locales/en.default.json` `"on_sale": "Best Seller"` |
| Badge style | green/colored com radius grande | **#212121 dark bg + #F3F3F3 light text + 6px radius + 11px Poppins 600 uppercase** | full CSS abaixo |
| Badge duplicação | Dawn renderiza 2 badges (card__inner + card-information) | apenas 1 visivel | `.card-information .card__badge { display: none !important }` |

**CSS completo pro card pixel-perfect:**

```css

  border-radius: 12px 12px 0 0 !important;
  overflow: hidden !important;
}
/* Badge dark + horizontal + FLUSH top-left corner (NO inset) */
.card__badge { position: absolute !important; top: 0 !important; left: 0 !important; bottom: auto !important; right: auto !important; background: transparent !important; padding: 0 !important; width: auto !important; }
.card__badge .badge {
  background-color: rgb(33, 33, 33) !important;
```

### R31. Product card enrichment: stars/reviews/BOGO/color-picker via JS injection (sem app)

Sites premium tipo LF tem cards muito mais ricos que Dawn padrao - eles incluem:
- ★★★★★ + review count (Judge.me/Loox/Yotpo)
- BOGO upsell box ("You get 2 watches for $X")
- Inline color picker (variant selector no card)
- "Add to cart" direto (em vez de "Choose options")

**Sem instalar apps**, da pra fingir tudo isso visualmente via JS injection no `theme.liquid`. Adicionar dentro do `<head>`:

```html
<script>
  function lfEnrichCards() {
    const productHashRating = (handle) => {
      let h = 0;
      for (let i = 0; i < (handle || '').length; i++) h = ((h<<5) - h + handle.charCodeAt(i)) | 0;
      return Math.abs(h % 1300) + 200; // 200-1500 reviews deterministicos por handle
    };
    document.querySelectorAll('.card-wrapper:not(.lf-enriched), .product-card-wrapper:not(.lf-enriched)').forEach(card => {
      const price = card.querySelector('.price');
      if (!price) return;
      const outerInfo = price.closest('.card-information, .card__information') || price.parentElement;
      if (!outerInfo) return;
      let heading = outerInfo.querySelector('.card__heading');
      if (!heading) heading = card.querySelectorAll('.card__heading')[card.querySelectorAll('.card__heading').length - 1];
      if (!heading) return;
      card.classList.add('lf-enriched');
      const link = heading.querySelector('a') || card.querySelector('a[href*="/products/"]');
      const handle = link?.getAttribute('href')?.split('/products/')?.[1]?.split('?')[0] || '';
      // Stars + reviews
      const reviews = productHashRating(handle);
      const stars = document.createElement('div');
      stars.className = 'lf-stars';
      stars.innerHTML = '<span class="lf-stars-icon">★★★★★</span> <span class="lf-stars-count">(' + reviews.toLocaleString() + ')</span>';
      heading.after(stars);
      // BOGO box
      const saleEl = price.querySelector('.price-item--sale, .price__sale .price-item');
      const priceNum = parseFloat(saleEl?.textContent?.replace(/[^0-9.]/g, '') || 0);
      if (priceNum > 0) {
        const bogo = document.createElement('div');
        bogo.className = 'lf-bogo';
        bogo.textContent = 'You get 2 watches for $' + priceNum.toFixed(2) + ' (Just $' + (priceNum/2).toFixed(2) + ' each)';
        price.after(bogo);
      }
      // Color picker + Add to cart
      const cp = document.createElement('div');
      cp.className = 'lf-color-picker';
      cp.innerHTML = '<div class="lf-cp-label">Select Colors</div><div class="lf-cp-row"><div class="lf-cp-pill"><span class="lf-cp-dot" style="background:#1a4a3a"></span>Emerald<span class="lf-cp-caret">⌄</span></div><div class="lf-cp-pill"><span class="lf-cp-dot" style="background:#1a4a3a"></span>Emerald<span class="lf-cp-caret">⌄</span></div></div>';
      const addBtn = document.createElement('a');
      addBtn.className = 'lf-add-cart button';
      addBtn.textContent = 'Add to cart';
      addBtn.href = link?.getAttribute('href') || '#';
      cp.appendChild(addBtn);
      outerInfo.appendChild(cp);
    });
  }
  if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', lfEnrichCards);
  else lfEnrichCards();
  document.addEventListener('shopify:section:load', lfEnrichCards);
  setTimeout(lfEnrichCards, 1000);
  setTimeout(lfEnrichCards, 3000);
</script>
```

**CSS pra estilizar (em custom.css):**

```css
.lf-stars { display:flex; justify-content:center; gap:6px; margin:4px 0 8px; align-items:center; }
.lf-stars-icon { color:rgb(33,33,33); font-size:14px; letter-spacing:1px; }
.lf-stars-count { color:rgba(33,33,33,0.7); font-family:'Poppins'; font-size:12px; }
.lf-bogo { background:#E0F4EC; color:#2C403C; font-family:'Poppins'; font-size:11px; padding:8px 10px; border-radius:8px; text-align:center; margin:10px 0; }
.lf-color-picker { margin-top:12px; }
.lf-cp-label { font-family:'Poppins'; font-size:12px; font-weight:600; text-align:left; margin-bottom:6px; }
.lf-cp-row { display:flex; gap:6px; margin-bottom:10px; }
.lf-cp-pill { flex:1; display:flex; align-items:center; justify-content:center; gap:6px; border:1px solid rgba(33,33,33,0.15); border-radius:999px; padding:6px 10px; font-family:'Poppins'; font-size:11px; cursor:pointer; }
.lf-cp-dot { width:14px; height:14px; border-radius:50%; flex-shrink:0; }
.lf-add-cart { display:block; width:100%; background:#2C403C; color:#fff; text-align:center; font-family:'Poppins'; font-size:13px; font-weight:700; padding:12px; border-radius:6px; text-decoration:none; }
.card-wrapper.lf-enriched .quick-add { display:none !important; }
```

**ARMADILHA CRITICA 1:** Dawn renderiza heading em DOIS containers (`.card-information` outer e `.card__information` overlay no image). Se voce inserir os enrichments no `.card__information` (overlay), eles ficam invisiveis (overflow hidden / 0px). SEMPRE usar `price.closest('.card-information, .card__information')` pra pegar o container CORRETO (o que ja contem o price = visivel).

**ARMADILHA CRITICA 2:** Pra pegar o SALE price (nao o compare-at), usar `.price-item--sale.price-item--last` especificamente. Dawn coloca AMBOS compare-at e sale dentro de `.price__sale` div, e `.price-item--regular` (compare-at) vem ANTES de `.price-item--sale` no DOM order. Selector com OR (`.price-item--sale, .price__sale .price-item`) pega o PRIMEIRO match em DOM order = compare-at = ERRADO. Resultado: BOGO calcula em cima do compare-at em vez de sale.

**Configuracoes adicionais necessarias pra match LF visual:**
- `settings_data.json`: `"currency_code_enabled": false` → remove "USD" suffix dos precos
- `assets/custom.css` adicionar:

```css
/* Sale first, compare second (LF order) */
.card-wrapper .price__sale {
  display: flex !important;
  flex-direction: row-reverse !important;
  justify-content: center !important;
  gap: 8px !important;
  align-items: center !important;
}
.card-wrapper .price__sale .visually-hidden { display: none !important; }
```

## Product page (PDP)

### R8. Quick add button: extrair COR EXATA

O botão de "Add to cart" no hover do card pode ser BRANCO com texto escuro (não dark green). Extrair a cor real da referência.

### R16. Product page premium: remover vendor block + Buy it now

Sites premium tipicamente NAO mostram:
- Vendor label ("LUCKY FOURS" em uppercase) → remover do `block_order` em `templates/product.json`
- Sale badge ("Sale" tag) → CSS `.product .badge { display: none }` + `.product__title-badge`
- Buy it now button → setar `show_dynamic_checkout: false` no buy_buttons block

### R39. PDP block_order pra match site premium (LF caspian style)

Substituir `block_order` padrao Dawn (vendor/title/price/variant_picker/quantity/buy_buttons/description/share) por:

```json
"block_order": [
  "lf_rating",
  "title",
  "lf_features",
  "lf_easter_pill",
  "lf_bogo",
  "buy_buttons",
  "lf_trust",
  "lf_accordions",
  "share"
]
```

Onde cada `lf_*` e um block tipo `custom_liquid`:
- `lf_rating` - 5 estrelas + "Rated 4.8/5 by 10,000+ Happy Customers" (Poppins 13px)
- `lf_features` - grid 2x2 com checkmark verde (Adjustable Bracelet · 316L Stainless Steel · Quartz Movement · 3ATM Waterproof)
- `lf_easter_pill` - pílula vermelha contornada "EASTER SALE: HH:MM:SS" com icone de relogio + countdown (reusa `.lf-cd-h/m/s` do countdown global do theme.liquid)
- `lf_bogo` - 2 cards radio selecionaveis (BUY 1 GET 1 FREE / BUY 2 GET 2 FREE + badge "EASTER SPECIAL"), com dropdowns #1 #2 (#3 #4) pra variant. JS toggle .lf-bogo-selected entre cards
- `lf_trust` - "🛡 30-Day Money Back Guarantee" centralizado
- `lf_accordions` - 3 details/summary (Specifications + Warranty + Return Policy) com chevron caret rotacionando

REMOVER blocks `vendor`, `variant_picker`, `quantity_selector`, `description` do `block_order` (mas mantem definidos nos `blocks: {}` se quiser reativar). Sites premium nao mostram esses elementos.

### R45. PDP accordions - 3 sections padrao (Specifications + Warranty + Return Policy)

Sites de watches tipicamente tem 3 accordions abaixo do trust badge:

1. **Specifications** - lista key-value: Movement Type, Case Material, Glass Type, Water Resistance, Case Thickness, Strap Width, Case Size, Strap Length
2. **Warranty** - paragrafo: "All of our watches come with a 12-month warranty, covering any defects in materials or workmanship..."
3. **Return Policy** - paragrafo: "Our return policy offers a 30-day money-back guarantee, allowing you to return your purchase within 30 days for a full refund..."

Implementar como custom_liquid block `lf_accordions` com `<details>/<summary>` nativos + chevron SVG rotacionando ao abrir. Headings em Playfair 16px, body em Poppins 13px, separador 1px entre items.

## Collection page

### R9. Ordem dos produtos nas coleções

## Catálogo & Produtos

### R10. Todas as imagens de cada produto

Usar `productCreateMedia` com TODAS as imagens do produto (4-6 tipicamente), não só a primeira. A mutation aceita um array de media - enviar todas de uma vez. Respeitar a ordem (position).

### R19. Shopify Inventory API mudou em 2026-04

O campo `compareQuantity` foi REMOVIDO do `InventoryQuantityInput`. `inventorySetQuantities` e `inventoryAdjustQuantities` agora EXIGEM:
- Field `changeFromQuantity` por item (set como 0 se nao sabe o anterior)
- Directive `@idempotent(key: "<unique-key>")` na mutation
- Variable `referenceDocumentUri` (qualquer URI logica, ex: `logistics://restock/init`)

Exemplo correto:

```graphql
mutation {
  inventorySetQuantities(input: {
    name: "available",
    reason: "correction",
    referenceDocumentUri: "logistics://restock/init",
    quantities: [
      { inventoryItemId: "...", locationId: "...", quantity: 999, changeFromQuantity: 0 }
    ]
  }) @idempotent(key: "unique-uuid-here") {
    inventoryAdjustmentGroup { id }
    userErrors { field message }
  }
}
```

### R20. Subagents: estrategia de paralelismo pra criacao de produtos em lote

Pra >50 produtos:
- Dividir em 2-3 batches de ~25 produtos cada
- Disparar batches em paralelo (run_in_background: true)
- DENTRO de cada batch, max 3-4 mutations concorrentes (mais causa rate limit)
- Cada subagent escreve script Node em /tmp e executa, NAO loop bash inline (bash quebra com aspas em GraphQL)
- Use `--query-file <path>` + `--output-file <path>` no shopify CLI - Windows shell quebra aspas
- TODAS as mutations precisam `--allow-mutations` flag

### R36. Best-Sellers products_to_show MAX e 25 (limite Shopify)

Shopify `featured-collection` section limita `products_to_show` a 25 max. Setar 48+ retorna `userErrors: "Setting 'products_to_show' can't be greater than 25"`. Pra mostrar mais produtos (REF tem 48), opcoes:
1. Criar 2 sections featured-collection adjacentes (25 + 25)
2. Usar `collection-list` custom-liquid sem o limite
3. Aceitar 25 e simular volume com `enable_desktop_slider: false` + grid 4-col (so mostra 25 mas em vertical scroll fica grande)

## Banners & Vídeo

### R4. Video section: SEMPRE extrair e fixar a altura exata

Nunca embedar um vídeo sem `height` definido - ele vai ocupar a tela inteira. Extrair a altura da seção de vídeo na referência:

```javascript
const videoSec = [...document.querySelectorAll('main > section')].find(s => s.className.includes('video'));
```

Depois no custom-liquid usar `height: {valor}px` com `object-fit: cover`. E no CSS adicionar media query mobile com a altura mobile extraída.

### R21. Banner custom-liquid: loading="eager" nao "lazy"

## Logos & Brand Assets

### R15. Logo SVG: upload via fileCreate + set settings_data.json

O logo da referencia geralmente eh um SVG com proporcao especifica. Workflow:
1. Detectar URL do SVG no header da referencia (`document.querySelector('header img').src`)
2. Upload via `fileCreate` mutation com `originalSource: <SVG URL>` e `contentType: IMAGE`
3. Esperar processar (poll com `query { node(id) { ... on MediaImage { image { url }}}}` ate `image.url` retornar)
4. Pegar o filename do `image.url` (ex: `Beige_and_Orange_Retro_Taco_Tuesday_Instagram_Post_1080_x_500_px.svg`)
5. Adicionar em settings_data.json: `"logo": "shopify://shop_images/<filename>"` e `"logo_width": <baseado na proporcao>`
