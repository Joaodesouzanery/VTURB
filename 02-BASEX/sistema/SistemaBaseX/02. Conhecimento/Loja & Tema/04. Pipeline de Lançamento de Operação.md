# Pipeline de Lançamento de Operação

Mapa canônico das fases pra lançar uma operação (loja própria ou cliente) end-to-end. Cada fase tem skill (ou ausência reconhecida), agente responsável, input esperado, output esperado e gate de saída.

> **Regra mãe:** cada fase termina com gate humano. Sem aprovação do gate, a próxima fase não inicia. Ver Gates de Validação Entre Fases.
> **Aplica a:** qualquer operação nova, da sua própria loja a uma loja que você monta para outra pessoa.

---

## Fase 0 — Briefing inicial

| Campo | Conteúdo |
|---|---|
| **Quando** | Primeira interação com nova operação (cliente novo ou negócio próprio novo) |
| **Input** | Pedido bruto do usuário: nicho, mercado, tipo, referências de marcas que admira |
| **Output** | Pasta da operação criada em `Minhas Lojas/{Marca}/` com o briefing inicial (`00. Briefing.md`) |
| **Agente** | `snps-orqx` (orquestração) ou `research-orqx` (se há benchmark externo a fazer) |
| **Gate de saída** | Usuário confirma: nicho, mercado, tipo, orçamento de tempo, prazo. Refs salvas. |
| **Skill** | LACUNA — criar `NN. Briefing de Nova Operação.md` |

## Fase 1 — Estratégia & nicho

| Campo | Conteúdo |
|---|---|
| **Input** | Briefing aprovado (Fase 0) |
| **Output** | Posicionamento de mercado, diferenciação, persona, oferta core, modelo de monetização |
| **Agente** | `council-orqx` (advisory board: Thiel, Hoffman, Munger, etc.) |
| **Consulta** | `02. Conhecimento/01. Estratégia & Negócio/` |
| **Gate de saída** | Documento de posicionamento aprovado pelo usuário, salvo em `{operacao}/01. Estrategia.md` |

## Fase 2 — Branding & identidade

| Campo | Conteúdo |
|---|---|
| **Input** | Posicionamento aprovado (Fase 1) |
| **Output** | Brand book (arquétipo Jung, paleta, tipografia, mood, tom de voz, materialidade) |
| **Agente** | `brand-orqx` (Neumeier, Aaker, Keller, Wheeler, Heyward, etc.) |
| **Consulta** | `02. Conhecimento/04. Branding & Identidade/` |
| **Gate de saída** | Brand book validado pelo usuário, salvo em `{operacao}/identidade/06. Brand Book.md`. **NÃO PULAR** — pular este gate custou três voltas de tema numa operação real, em maio de 2026 |

---

## Fase 3 — Briefing visual & geração de assets

| Campo | Conteúdo |
|---|---|
| **Input** | Brand book validado (Fase 2) |
| **Output** | Lista de assets visuais aprovados (hero, banners, lifestyle, pack shots, founder, logo, ícones, vídeos) com catálogo rastreável |
| **Agente** | Skill direta + geração por IA (padrão) ou foto real |
| **Consulta** | 108. Refazer Criativo com a Sua Marca (geração de imagem por IA) |
| **Gate de saída** | Todos os slots aprovados pelo usuário, salvos em `{operacao}/identidade/assets/` com catálogo |
| **Skill** | 60. Briefing do Criativo em Video — comando `/briefing-criativos` |

---

## Fase 4 — Setup da loja

| Campo | Conteúdo |
|---|---|
| **Input** | Brand book + decisão de mercado(s) |
| **Output** | Loja Shopify configurada: políticas, mercados, frete, impostos, payment, locations |
| **Skill** | `04. Configurar a Loja para Vender no Mundo` (496 linhas, 6 fases scriptadas) |
| **Pré-requisito** | Plano Shopify ativo, conta autenticada via CLI |
| **Gate de saída** | Checklist da skill 04 completo, loja com `online_store.disabled = false` (ou intencional draft) |

---

## Fase 5 — Tema/site

| Campo | Conteúdo |
|---|---|
| **Input** | Brand book + assets aprovados (Fase 3) + (opcional) URL de referência pra clonar |
| **Output** | Tema Dawn customizado refletindo identidade, com assets reais e dados completos |
| **Skills** | `110. Montar a Loja a Partir de uma Referencia.md` (reconhecimento + extração, ramo clone) → `116. Colocar a Marca na Loja.md` (construção + população, modos clone OU greenfield) |
| **Gate visual** | `08. QA Visual da Loja.md` — 8 viewports × 13 áreas, antes de declarar fase completa |
| **Agente** | Skills diretas + `design-orqx` (revisão de hierarquia visual) |
| **Gate de saída** | Diff TEMA zerado em [[08. QA Visual da Loja]] OU entrega parcial documentada. Aprovação visual do usuário antes de qualquer push final. Catálogo de patches [[05. Patches Pixel-Perfect Dawn]] aplicado no Passo 14 da 02b. |

---

## Fase 6 — Produtos

| Campo | Conteúdo |
|---|---|
| **Input** | Catálogo da operação (planilha, scraping de referência, briefing) |
| **Output** | Produtos criados/editados, traduzidos e com SEO no Shopify |
| **Skills** | `03. Editar Produtos da Loja`, `05. Traduzir Produtos Shopify.md`, `06. Gerar SEO Produtos Shopify.md` |
| **Ordem** | 03 (criar/editar) → 06 (SEO no idioma master) → 05 (traduzir pros mercados extras) |
| **Gate de saída** | Amostra de 3-5 produtos validada pelo usuário antes de processar lote inteiro |

---

## Fase 7 — Tráfego & aquisição

| Campo | Conteúdo |
|---|---|
| **Input** | Loja com tema + produtos + assets (Fases 4, 5, 6) |
| **Output** | Pixels instalados, campanhas estruturadas, criativos rodando, dashboards de leitura |
| **Agente** | `paidmedia-orqx` (Sobral, Burns, Mandalia, Aslam, Pittman, etc.) |
| **Consulta** | `02. Conhecimento/05. Tráfego & Aquisição/` |
| **Gate de saída** | Primeira campanha publicada com tracking validado (Pixel disparando), orçamento aprovado |
| **Skill** | LACUNA — sem skill canônica |

---

## Fase 8 — Validação & QA

| Campo | Conteúdo |
|---|---|
| **Quando** | Transversal: ao final de toda fase E como sweep final antes de "go live" |
| **Skill terminal** | [[08. QA Visual da Loja]] — matriz 8 viewports × 5 páginas + extração via `getComputedStyle` das 13 áreas-foco |
| **Agente** | `quality-gate` |
| **Output** | Relatório de QA visual com matriz de screenshots, tabela de diff classificada (TEMA/APP/CONFIG), checklist final |
| **Gate** | Go/no-go pra divulgar a operação publicamente. Diff TEMA zerado ou entrega parcial documentada com ações pendentes. |

## Cadência de gates (resumo executivo)

| Após fase | Gate humano obrigatório |
|---|---|
| 0 | Aprovar briefing |
| 1 | Aprovar posicionamento |
| 2 | Aprovar brand book |
| 3 | Aprovar lote de assets |
| 4 | Confirmar setup (preview de checkout) |
| 5 | Aprovar validação visual multi-breakpoint |
| 6 | Aprovar amostra de produtos antes de lote |
| 7 | Aprovar primeira campanha + budget |
| 8 | Go/no-go final |

Nenhum auto-encadeamento sem confirmação explícita do usuário — ver Gates de Validação Entre Fases.

## Duas lições que este pipeline aprendeu apanhando

**Gate pulado cobra depois.** Numa operação, a Fase 2 foi dada por pronta sem o gate de identidade. O tema voltou três vezes: versão 1, revert, versão 2, versão 3. Cada volta custou mais que o gate teria custado.

**Nem toda loja nasce de um clone.** Uma operação sem URL de referência para clonar expôs a Fase 5, que só cobria o caminho do clone. Daí a bifurcação: extrair de uma referência é um ramo, construir do zero é outro, e `116. Colocar a Marca na Loja` tem modo greenfield por causa disso.
