## 2. Frameworks e modelos mentais

> Cada framework recebe nome, explicacao, quando aplicar e citacao verbatim com timestamp.

### 2.1 Modo Fila (Queue Mode) desde o dia 1

**O que e:** Arquitetura em que o n8n roda com processos separados (editor, webhook e worker), em vez de um único processo monolítico. Cada função vira um serviço isolado no EasyPanel.

**Como funciona:**
1. **Editor** — instância do n8n onde você trabalha (constrói os workflows). É a que mais se usa.
2. **Webhook** — instância que recebe as requisições de produção (o endpoint público que dispara os fluxos).
3. **Worker** — instância que só executa o trabalho pesado das automações. Não tem interface, ninguém acessa.
4. Todos compartilham o mesmo banco Postgres e usam Redis como fila entre webhook e worker.

**Quando aplicar:** Desde a primeira instalação, mesmo iniciante, para já nascer escalável.

**Quando NAO aplicar:** O vídeo não apresenta contraindicação. O argumento é que instalar em modo fila desde o início não custa mais e evita retrabalho.

> "Por que a gente já instala logo em modo fila? Porque quando você escalar, quando você tiver mais clientes... você não vai travar a sua máquina, você não vai travar a sua VPS, porque você vai ter instalado da forma correta já desde o dia 1."
> — [00:01:23]

### 2.2 Gerador de Esquema (agentes.criador.digital)

**O que e:** Ferramenta web do autor que gera automaticamente o esquema de serviços (schema) para colar no EasyPanel. Recebe nome do projeto, domínio base e opção de instalar Evolution API, e devolve tanto o schema quanto a linha SQL do banco e a lista de subdomínios.

**Como funciona:**
1. Acessar `agentes.criador.digital` → recursos → N8N → instalação N8N (link direto: N8N/instalação).
2. Definir nome do projeto (ex.: "YouTube") e domínio base (ex.: `criador.digital`).
3. Escolher instalar ou não a Evolution API.
4. Gerar as chaves/senhas (aleatórias ou manuais) para os bancos e a chave de encriptação.
5. Saída (Output): **EasyPanel Schema** (com nota do autor de que Docker viria no futuro).

**Quando aplicar:** Para montar o stack sem escrever o docker-compose/schema à mão.

**Quando NAO aplicar:** Não aplicável — no vídeo é sempre o caminho recomendado.

> "Bom, eu facilitei a sua vida bastante, né, criando esse criador de esquema, agora não precisa mais atualizar os domínios automaticamente, comparado com o último vídeo que eu postei sobre o assunto no ano passado."

## 4. Heuristicas e regras

- **Instalar em modo fila desde o dia 1** — evita travar a VPS quando escalar; "instalado da forma correta e escalável para poder aguentar o tranco" [00:01:49]
- **VPS recomendada: Hostinger KVM2, 8 GB de RAM** — "está mais que suficiente para rodar um N8N em modo fila, robusto e profissional"; upgrade depois se precisar [00:02:15]
- **Contratar 24 meses** — o maior desconto de todos é no plano de 24 meses [00:02:32]
- **Cupom de 10%** — aplicável nos planos KVM2 ou maiores (link + cupom na descrição) [00:02:05]
- **Escolher EasyPanel como sistema operacional no carrinho** — se pular, dá pra reinstalar depois via "Configuração de SO e painel" [00:02:56]
- **NUNCA clicar em "reinstalar OS" numa VPS que já tem coisa** — "porque senão vai deletar tudo"; só reinstalar em VPS zerada [00:04:12]
- **Precisa de um domínio próprio** — sem domínio não instala; `.site` e `.cloud` são os mais baratos, no máximo ~R$20 [00:05:43]
- **Worker não precisa de registro DNS** — "ele só trabalha, a gente nem acessa ele"; só editor, webhook e evolution precisam de subdomínio [00:10:52]
- **Publicar o workflow antes de testar o webhook de produção** — "senão o Webhook de produção não vai funcionar" [00:14:59]
- **Sempre testar o n8n após instalar** — "é uma boa prática; se você fizer isso e não tá funcionando, você errou em alguma parte" [00:15:23]

## 8. Aplicacao no nosso contexto

> Conexão com o projeto do bot BaseX (WhatsApp em grupos de alunos; Evolution API + n8n + Claude; tirar dúvidas + gestão).

**O que isso muda na nossa operacao:**
Este vídeo é a receita do servidor que o bot BaseX vai usar. O stack proposto (n8n modo fila + Evolution API + Postgres + Redis num EasyPanel sobre VPS) cobre exatamente as três peças do bot: a **Evolution API** conecta o WhatsApp (grupos de alunos), o **n8n em modo fila** orquestra os fluxos de resposta e gestão, e o **worker separado** garante que picos de mensagens em vários grupos não travem a máquina. A separação editor/webhook/worker é importante porque um bot de grupo pode receber rajadas de mensagens; sem fila, o processo único engargala. A chamada ao Claude entra como nó HTTP dentro dos workflows do n8n (o vídeo não cobre a integração com Claude, só o servidor base).

Parâmetros práticos extraídos para dimensionar o servidor do bot:
- **VPS:** Hostinger KVM2, 8 GB de RAM (suficiente para n8n modo fila + Evolution API; upgrade depois se escalar).
- **Painel:** EasyPanel sobre Ubuntu 24.04 (cria os serviços a partir de schema; sem docker-compose manual).
- **Componentes:** Evolution API, n8n Editor, n8n Webhook, n8n Worker, Postgres, Redis.
- **Domínio + DNS:** um subdomínio por serviço na Cloudflare (registro A → IP do EasyPanel). Para o bot: `evolution.` (WhatsApp), `editor.` (construir fluxos), `webhook.` (endpoints de produção), `painel.` (acesso ao EasyPanel). Worker não precisa.
- **Banco:** criar via console Postgres Client (colar a linha SQL do gerador).
- **Custo:** VPS KVM2 (com cupom 10%, plano 24 meses) + domínio barato (~R$20 no `.site`/`.cloud`). Sem custo de licença do n8n (license key gratuita libera folders/tags/debug).

**Acao concreta sugerida:**
- [ ] Contratar/confirmar VPS Hostinger KVM2 (8 GB) com EasyPanel (Ubuntu 24.04) para o bot BaseX
- [ ] Gerar o schema em `agentes.criador.digital` com Evolution API marcada e subir editor/webhook/worker + Evolution + Postgres + Redis
- [ ] Criar registros A na Cloudflare para evolution/editor/webhook/painel apontando ao IP do EasyPanel
- [ ] Criar o banco Postgres via console e ativar a license key gratuita do n8n
- [ ] Validar o webhook de produção com um POST de teste (Postman) antes de plugar a Evolution API nos grupos de alunos
- [ ] Planejar a integração Claude como nó HTTP dentro do n8n (fora do escopo deste vídeo, aprofundar em material próprio)
