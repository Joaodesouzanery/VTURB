# Agente Dify no N8N para WhatsApp | Curso Automações para WhatsApp (Aula 6)

> Aula prática que mostra, passo a passo, como conectar um agente de IA criado na plataforma Dify a um fluxo n8n de WhatsApp, resolvendo o problema de streaming e dando memória de conversa ao bot via Conversation ID salvo em banco de dados.

**Canal:** [Rhavi Criador Digital](https://www.youtube.com/@criadordigital) · **Duracao:** 00:22:12 · **Publicado:** 2025-04-06 · [Assistir](https://www.youtube.com/watch?v=PLgu-YK2dmY)

## 1. Tese central

Dá pra transformar um agente de IA hospedado na Dify no cérebro de um chatbot de WhatsApp orquestrado pelo n8n, mantendo o fluxo n8n o mais enxuto possível. O segredo técnico é chamar a API de chat-messages da Dify via bloco HTTP Request, converter a resposta em streaming para um bloco único de texto com um nó de código, e persistir o Conversation ID no banco de dados para que o agente lembre com quem está falando entre uma mensagem e outra.

> "O objetivo aqui é trazer um fluxo mais simples possível, o mais enxuto possível [...] Para você conseguir da simplicidade ir para a complexidade."
> [00:00:12]

## 2. Frameworks e modelos mentais

> Cada framework recebe nome, explicacao, quando aplicar e citacao verbatim com timestamp.

### 2.1 Ramificação por existência de Conversation ID (IF antes de chamar a Dify)

**O que e:** um nó IF que decide, antes de chamar a Dify, se aquele usuário já tem uma conversa iniciada (Conversation ID salvo) ou se é o primeiro contato. Cada ramo aponta para uma versão diferente da chamada HTTP.

**Como funciona:**
1. Nó IF pergunta: o Conversation ID não existe? Se verdadeiro, é primeira conversa.
2. Ramo "true" (primeira vez) segue para o HTTP chamado "Dify sem ID" (chamada sem conversation_id, deixando a Dify gerar um novo).
3. Ramo "false" (já existe) segue para o HTTP chamado "Dify com ID", que injeta o Conversation ID recuperado do banco.

**Quando aplicar:** sempre que o agente precisa de memória de conversa persistente por usuário.

**Quando NAO aplicar:** bots stateless de resposta única, onde cada mensagem é independente e não precisa de histórico.

> "A gente precisa verificar, antes de começar a chamar o DeFi, para ver se ele já tem o Conversation ID ou não, se foi a primeira conversa ou não. Para isso, a gente vai usar o nosso famoso nódulo if."
> [00:11:56]

### 2.2 Streaming para bloco via nó de código

**O que e:** a Dify no modo agente só responde em streaming (token por token). O n8n precisa de um texto único, então um nó de código JavaScript junta os pedaços numa resposta só.

**Como funciona:**
1. O HTTP Request recebe a resposta da Dify fragmentada (streaming).
2. O nó de código faz trim e split sobre os fragmentos.
3. Junta tudo em uma resposta única e ainda expõe o Conversation ID e metadados da mensagem.

**Quando aplicar:** toda vez que consumir a Dify em modo agente dentro do n8n.

**Quando NAO aplicar:** se a API respondesse em bloco nativamente (o modo agente da Dify não permite isso).

> "Na verdade, na DeFi, esse modo agente aqui [...] ele não permite modo bloco. Ele só permite modo streaming. Então, o que a gente vai ter que fazer? A gente vai ter que vir aqui e utilizar um código, um bloco de código."
> [00:07:38]

## 4. Heuristicas e regras

Regras-de-bolso, atalhos mentais, principios que o autor enfatiza:

- **Puxar o valor sempre do nó original onde ele apareceu, não do último nó.** Assim, se você inserir um novo nó entre dois, a referência não quebra e vem com o identificador certo (ex: pegar o convID do nó Search, não do IF). [00:13:41]
- **Usar o número de telefone como identificador único do usuário.** É estável e natural no contexto WhatsApp. [00:09:19]
- **Configurar o timezone São Paulo na ferramenta Current Time.** Sem isso o agente devolve a hora errada (ex: 12h42 em vez de 9h42). [00:02:03]
- **Manter o fluxo simples de propósito nos fundamentos.** Ir da simplicidade para a complexidade, não o contrário. [00:00:17]
- **Salvar o Conversation ID a cada interação, mesmo repetido, tem valor.** Serve para saber pelo campo Last Modified quais usuários acessaram o bot por último. É decisão caso a caso; dá pra colocar um IF para não regravar, mas o autor prefere manter. [00:15:08]
- **Deixar tudo nomeado e anotado.** Renomear nós (Dify sem ID, Dify com ID, Verifica ID, User existe) para saber o que cada coisa faz. [00:14:38]

## 8. Aplicacao no nosso contexto

> Esta secao conecta o conhecimento absorvido com o projeto do bot BaseX (WhatsApp de grupos de alunos, Evolution API + n8n + Claude, para tirar dúvidas e apoiar gestão).

**O que isso muda na nossa operacao:**
O vídeo fornece o padrão exato de como plugar um agente de IA num fluxo n8n de WhatsApp, e o padrão é agnóstico de provedor. A anatomia é: gatilho da Evolution API entra no n8n, normaliza a mensagem e o número do remetente, um nó IF decide se o usuário já tem contexto salvo, um bloco HTTP Request chama o cérebro de IA, um nó de código consolida a resposta, e a Evolution devolve o texto ao WhatsApp. No bot BaseX de alunos, esse esqueleto se mantém trocando apenas o "cérebro".

Comparação Dify vs Claude direto para o cérebro do bot:

| Critério | Dify (o vídeo) | Claude direto (API Anthropic) |
|----------|----------------|-------------------------------|
| Memória de conversa | Gerenciada pela própria Dify via Conversation ID; basta salvar e reenviar o ID | Sem estado nativo; precisamos montar o histórico e enviar o array de mensagens a cada request (memória em Airtable/Supabase) |
| Modo de resposta | Modo agente só em streaming; obriga nó de código para virar bloco | Podemos pedir resposta em bloco direto, ou streaming se quisermos; menos gambiarra |
| Ferramentas (tools) | Interface visual (Time, Visão, agendamento) ligada no painel Dify | Tool use definido no payload da request; controle total no n8n, mais trabalho manual |
| Prompt e contexto | Editado no estúdio Dify (instruções, variáveis, documentos) | Prompt de sistema montado no n8n; versionável junto do fluxo |
| Custo e dependência | Camada extra (Dify) + chave OpenAI por baixo; dois pontos de falha | Uma única dependência (Anthropic); menos peças |
| Curva para o aluno | Visual, rápido de mostrar em aula | Exige entender payload de API e montagem de histórico |

Leitura para o bot BaseX: como o bot precisa de dúvidas com memória por aluno e apoio de gestão, Claude direto tende a ser mais enxuto e barato a longo prazo (menos camadas, resposta em bloco sem nó de conversão), mas exige montar a memória à mão (salvar histórico por número de telefone em Supabase/Airtable e reenviar). A Dify entrega memória e RAG de graça no painel, bom para protótipo rápido ou quando o aluno for gerenciar o agente sem código. Independente da escolha, o padrão de plugagem do vídeo (HTTP Request como ponte, IF por estado do usuário, número de telefone como chave, nó de código consolidando a resposta) é diretamente reaproveitável.

**Como plugar um agente de IA no fluxo n8n (extraído do vídeo, generalizável):**
1. Ponte via bloco HTTP Request (Import CURL quando o provedor fornece o comando pronto).
2. Autenticação no header com "Bearer " + chave de API.
3. Enviar no corpo: a mensagem do usuário, o identificador do usuário (número de telefone) e o identificador de conversa quando já existir.
4. IF antes da chamada para separar primeiro contato de contato recorrente.
5. Persistir o identificador de conversa (ou o histórico) no banco por usuário.
6. Nó de código para consolidar a resposta antes de devolver à Evolution.

**Acao concreta sugerida:**
- [ ] Decidir cérebro do bot BaseX de alunos: Claude direto (recomendado por custo/simplicidade) vs Dify (protótipo rápido).
- [ ] Se Claude direto: implementar memória por número de telefone em Supabase (equivalente ao Conversation ID da Dify), reenviando histórico a cada request.
- [ ] Reusar o esqueleto Evolution, IF por estado, HTTP Request, nó de código no fluxo n8n do bot.
- [ ] Guardar Last Modified por aluno para métrica de quem acionou o bot por último (ideia direta do vídeo).
