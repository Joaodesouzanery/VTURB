# AULA 7: Transcrição de Áudio no N8N | Treinamento Agentes WhatsApp

> Aula prática de montar, no n8n, a etapa que recebe áudio de WhatsApp e converte em texto antes de mandar pro agente de IA, usando a Avisa API e o nó Transcribe a Recording da OpenAI.

**Canal:** [Rhavi Criador Digital](https://criador.digital)  · **Duracao:** 00:14:52 · **Publicado:** 2026-05-22 · [Assistir](https://www.youtube.com/watch?v=KXBmAkj2wu4)

---

## 1. Tese central

Antes de mandar qualquer coisa pro agente de IA, o fluxo do n8n precisa classificar o tipo de mensagem (texto, áudio, imagem, documento, vídeo) e transformar áudio em texto, porque a LLM só entende texto. O autor defende processar o áudio logo no início do fluxo e nunca ficar empurrando o arquivo binário de nó em nó sem necessidade, deixando o fluxo mais limpo e preparado pra crescer. Nesta aula ele faz isso com a Avisa API (áudio chega como arquivo binário pronto); a versão com Evolution API fica pra aula seguinte.

## 2. Frameworks e modelos mentais

> Cada framework recebe nome, explicacao, quando aplicar e citacao verbatim com timestamp.

### 2.1 Classificar antes de processar (roteamento por Switch)

**O que e:** usar o nó Switch pra rotear cada mensagem recebida conforme o tipo, criando saídas nomeadas (texto, áudio, imagem, documento, vídeo) em vez de tratar tudo igual.

**Como funciona:**
1. Ignora primeiro as mensagens de grupo (não transcreve áudio de grupo).
2. Puxa o campo `type` do evento; quando `type` é igual a `text`, é mensagem normal.
3. Quando é mídia, desce até o `media_type` e roteia: `PTT` é áudio, `image` é imagem, `document` é documento, mais a rota de vídeo.
4. Renomeia cada saída (Rename Output) pra visualizar por nome, não por 0, 1, 2, 3.

**Quando aplicar:** bot de WhatsApp que precisa aceitar mais de um formato de entrada e mandar cada um pro tratamento certo.

**Quando NAO aplicar:** o autor não cita contraindicação. Não aplicável ao vídeo se o bot só recebe texto puro, aí o Switch é dispensável.

> "O switch, ele faz o quê? Ele faz um roteamento com mais de uma opção. O win, o if, ele é só verdadeiro ou falso. O switch, a gente pode colocar um tanto de opção possível."
> — [00:05:04]

### 2.2 Setar a variável só depois de ter texto

**O que e:** só gravar a variável de conteúdo da mensagem (o "set variáveis") no final do fluxo, depois que o áudio já virou texto, porque a IA vai consumir texto e não o arquivo de áudio.

**Como funciona:**
1. Deixa o nó de setar variáveis no finalzinho do fluxo.
2. Ignora grupos antes de tudo.
3. Transcreve o áudio e junta as saídas com o Merge.
4. No fim, referencia o conteúdo já em texto pra gravar a variável.

**Quando aplicar:** sempre que o fluxo puder receber áudio, pra não passar binário adiante à toa.

**Quando NAO aplicar:** o autor diz que renomear/reorganizar referências não precisa ser feito toda vez, só quando de fato se coloca um nó novo no meio do fluxo.

> "Eu preciso setar a variável uma vez que eu tenho texto. Porque a LLM, as inteligências artificiais, o nosso agente, vai entender texto. Então, a gente precisa setar um texto aqui e não mandar um áudio para ele. E quanto menos a gente ficar empurrando o arquivo de áudio de nó em nó, melhor."
> — [00:01:27]

## 4. Heuristicas e regras

Regras-de-bolso, atalhos mentais, principios que o autor enfatiza:

- **Quanto menos empurrar o arquivo de áudio de nó em nó, melhor** — processa o áudio logo no início pra o fluxo ficar mais eficiente [00:01:40]
- **Ignora grupo primeiro, seta variável depois** — não transcreve áudio de grupo e só grava a variável quando já tem texto [00:00:56]
- **Na dúvida sobre a nomenclatura da API, vai na documentação** — no caso da Avisa API a doc está no Postman; foi assim que ele descobriu que era `document` e não `archive` [00:06:42]
- **Sempre referencia a mensagem do lugar certo** — puxando do nó correto (Merge), dá pra fazer modificação maluca no meio que o fluxo não quebra [00:14:08]
- **Renomeia a saída do Switch** — troca 0, 1, 2, 3 por texto, áudio, imagem, documento pra conseguir visualizar e saber o que é cada rota [00:07:32]
- **No campo Input Field da transcrição, usa File puro** — só a palavra File, sem expressão e sem referenciar nó, porque File é o container do arquivo [00:09:37]

## 8. Aplicacao no nosso contexto

> Esta secao conecta o conhecimento absorvido com o que ja existe no vault (bot BaseX de grupos de alunos no WhatsApp, com Evolution API + n8n + Claude).

O bot BaseX roda nos grupos de WhatsApp dos alunos pra tirar dúvidas e apoiar a gestão. Alunos frequentemente mandam a dúvida em áudio, e o Claude só processa texto. Esta aula entrega exatamente a etapa que falta: converter o áudio em texto dentro do n8n antes de chamar o agente.

**O que o vídeo entrega de reaproveitável (só o que está no vídeo):**
- **Serviço de transcrição:** nó Transcribe a Recording da OpenAI dentro do n8n (recurso áudio, operação transcrever uma gravação).
- **Node de captura:** nó Switch pra classificar por `media_type`; áudio de WhatsApp cai na rota onde `media_type` é igual a `PTT`.
- **Campo de entrada:** no nó da OpenAI, trocar o Input Field de `data` pra `File` puro, porque File é o container do binário.
- **Passar o binário adiante:** ligar Include Other Input Fields em All pra o arquivo não ficar parado no nó set e chegar até a transcrição.
- **Consolidação:** nó Merge (5 inputs) juntando as rotas, e o conteúdo final referenciado como `json.texto` (áudio transcrito) ou `message.conversation` (texto puro).

**Ressalvas de contexto (o vídeo não cobre):**
- O bot BaseX usa **Evolution API**, não Avisa API. Nesta API o áudio chega em **Base64** e precisa ser convertido em arquivo antes de transcrever; o autor trata isso só na próxima aula [00:08:40].
- **Formato ogg:** não mencionado no vídeo. Áudio de WhatsApp aparece aqui apenas como binário com `media_type` PTT; o formato de container não é citado, então não inventar.
- **Custo da transcrição:** não mencionado no vídeo. A OpenAI cobra por transcrição, mas nenhum valor aparece na aula.

**Acao concreta sugerida:**
- [ ] Replicar a rota de áudio (Switch por `media_type` PTT, transcrição, Merge, set variáveis) no fluxo do bot BaseX, adaptando a captura pra Evolution API (Base64 para arquivo)
- [ ] Confirmar o formato real do áudio que a Evolution manda e medir custo por transcrição antes de escalar pros grupos de alunos

## 11. Glossario (se aplicavel)

| Termo | Significado |
|-------|-------------|
| Avisa API | API de WhatsApp usada na aula, escolhida por estabilidade; entrega áudio como arquivo binário |
| Evolution API | API de WhatsApp alternativa; entrega áudio em Base64, exige conversão pra arquivo (próxima aula) |
| PTT | Valor de `media_type` que identifica mensagem de áudio de WhatsApp (push to talk) |
| Base64 | Texto que codifica um arquivo; na Evolution o áudio chega assim e precisa virar arquivo |
| Switch | Nó do n8n que roteia com múltiplas saídas, ao contrário do if (só verdadeiro/falso) |
| Merge | Nó do n8n que junta várias saídas num só ponto pra organizar o fluxo |
| Transcribe a Recording | Operação do nó OpenAI no n8n que transcreve um áudio em texto |
| Include Other Input Fields | Opção do nó que faz carregar campos além do JSON (ligada em All pra passar o binário) |
| RAG | Recuperação aumentada por geração; citado como destino de documentos no banco vetorial |
