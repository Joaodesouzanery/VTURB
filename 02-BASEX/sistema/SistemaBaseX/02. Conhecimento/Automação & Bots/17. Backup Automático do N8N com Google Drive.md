# AULA 3.5: Backup automático no N8N com Google Drive Passo a Passo

> Tutorial que monta, nó por nó, um fluxo de n8n que agenda backup diário de todos os workflows, separa os ativos dos desativados e sobe cada um como arquivo JSON numa pasta datada do Google Drive, com restauração via import.

**Canal:** [Rhavi Criador Digital](https://www.youtube.com/@criadordigital) · **Duracao:** 00:19:23 · **Publicado:** 2026-04-08 · [Assistir](https://www.youtube.com/watch?v=l41nizCjwG8)

---

## 1. Tese central

Um workflow do n8n é, no fundo, apenas JSON. Por isso dá pra automatizar o backup de todos eles: um gatilho de tempo dispara diariamente, o fluxo lista todos os workflows pela API do próprio n8n, converte cada um em arquivo JSON e envia para uma pasta datada no Google Drive, separando ativos de desativados. Se a instalação cair ou precisar migrar de servidor, basta reimportar o JSON. A proposta do autor é fazer isso da forma mais simples possível, mas segura e escalável.

## 2. Frameworks e modelos mentais

> O vídeo entrega um único framework prático: a arquitetura do fluxo de backup. Abaixo, decomposto nó por nó.

### 2.1 Fluxo de Backup Automático do n8n no Google Drive

**O que e:** Um workflow do n8n que arquiva, de forma agendada, todos os outros workflows da instância como arquivos JSON no Google Drive, organizados por data e por status (ativo/desativado).

**Como funciona:**
1. **Trigger de tempo (Schedule Trigger)** nomeado "Agendar Backup", com intervalo de 1 dia (configurável em segundos, dias, semanas, com hora e minuto definidos). [00:00:42]
2. **Nó Set** define uma variável única: o ID da pasta raiz de backup no Google Drive (pego da URL da pasta, tudo depois de `folders/`). [00:01:17]
3. **Criar subpasta (Google Drive, recurso Folder)** cria uma subpasta datada dentro da pasta raiz, usando a variável `$now` formatada com data + hora + minuto + segundo (garante nome único). A pasta mãe é referenciada por ID vindo do nó Set. [00:03:59]
4. **Criar pasta ativo** e **Criar pasta desativado**: duas subpastas dentro da pasta datada, referenciando o ID da subpasta anterior via `$('Criar subpasta').item.json.id`. Convenção de cor: verde para ativo, vermelho para desativado. [00:07:11]
5. **Credencial da API do n8n**: cria uma API Key nas Settings > n8n API (sem expiração, `No Expiration`) e uma Base URL no formato `SEU_ENDERECO/api/v1`. [00:11:42]
6. **Nó n8n (recurso Workflow, operação Get Many)** lista todos os workflows da instância como JSON. [00:13:38]
7. **Nó IF** separa em dois caminhos: workflows ativos (true) e desativados (false). [00:14:48]
8. **Convert to File (operação Convert to JSON)** transforma cada workflow (uma linha de texto JSON) em arquivo `.json` separado, um por item, nomeando o arquivo com o nome do próprio fluxo (`nome_do_fluxo.json`) em vez do genérico `file.json`. [00:15:19]
9. **Upload (Google Drive)** sobe cada arquivo para a pasta ativo ou desativado correspondente. [00:17:16]

**Quando aplicar:** Qualquer instância de n8n em produção cujos workflows não podem ser perdidos (VPS própria, self-hosted). Especialmente antes de escalar a operação.

**Quando NAO aplicar:** Não aplicável de forma explícita no vídeo. O autor apenas cita alternativa complementar (backup no GitHub) para quem quer redundância extra.

> "E olha só que genial. Os fluxos do N8N são nada mais nada menos que JSON. É tudo JSON, isso aqui são os meus fluxos."
> — [00:14:01]

## 4. Heuristicas e regras

- **Escreva um ponto após qualquer variável no n8n pra ver as opções** — o editor sugere métodos e campos (`.format`, `.item`, `.json`, etc); é assim que o autor diz que aprende todos os dias. [00:05:03]
- **Nomeie subpastas com data + hora + minuto + segundo** — garante nome único e evita colisão se o fluxo rodar duas vezes no mesmo dia. [00:06:29]
- **Prefixe o nome com "ativo"/"desativado" no começo** — assim aparecem ordenados no topo e são fáceis de achar. [00:08:24]
- **Nunca deixe a API Key com expiração de 30 dias** — troque para `No Expiration`, senão o backup para de funcionar sozinho depois de 30 dias. [00:12:59]
- **Nunca mostre sua API Key do n8n pra ninguém** — quem tiver a chave ganha acesso à sua instância; o autor diz que vai gerar uma nova depois de gravar. [00:12:23]
- **Referencie a pasta por ID, não por lista ou URL** — nem sempre é fácil achar a pasta na busca; o ID conecta direto. [00:06:53]
- **Renomeie o arquivo de saída com o nome do fluxo** — sem isso todos os backups saem como `file.json` e ficam indistinguíveis. [00:16:07]

## 8. Aplicacao no nosso contexto

> Conecta com o projeto do bot da BaseX: atendimento em grupos de WhatsApp de alunos rodando em Evolution API + n8n + Claude, cobrindo dúvidas dos alunos e gestão. Todo esse atendimento vive dentro de workflows do n8n. Se a VPS cair, for corrompida ou precisar migrar, os fluxos do bot se perdem sem backup. Este fluxo é a rede de segurança que protege a operação do bot.

**O que isso muda na nossa operacao:**
Hoje os workflows do bot (fila de mensagens, roteamento recepcionista/agendamento, integração com Claude, verificação de aluno no banco) existem só na instância viva do n8n. Implantar este fluxo de backup significa que qualquer incidente na VPS ou update quebrado do n8n vira um problema de 2 minutos (reimportar o JSON), não um retrabalho de reconstruir o bot inteiro. A separação ativo/desativado ajuda a identificar rápido quais são os fluxos de produção do bot versus testes.

**Como automatizar o backup do bot (concreto):**
- [ ] Criar pasta raiz "Backup n8n BaseX" no Google Drive da operação e copiar o ID (tudo após `folders/` na URL).
- [ ] Importar/replicar o fluxo: Schedule Trigger (1 dia) → Set (ID da pasta) → Criar subpasta datada (`$now`) → Criar pasta ativo (verde) e desativado (vermelho) → n8n Get Many Workflows → IF ativo/desativado → Convert to File (JSON, arquivo por fluxo, nome = nome do fluxo) → Upload no Drive.
- [ ] Gerar API Key do n8n em Settings > n8n API com `No Expiration`; Base URL = `endereco-do-n8n/api/v1`; guardar a chave fora do vault (nunca commitar).
- [ ] Ajustar o horário do cron para uma janela de baixa atividade do bot (ex: madrugada BRT).
- [ ] Validar a restauração de ponta a ponta: baixar um JSON do Drive e reimportar num workflow novo antes de confiar no backup.
- [ ] Avaliar segunda camada no GitHub (repo privado) para redundância, como o autor sugere.

## 11. Glossario (se aplicavel)

| Termo | Significado |
|-------|-------------|
| Trigger | Nó de gatilho que inicia o fluxo (aqui, agendado por tempo) |
| Nó Set | Nó que define e guarda variáveis no fluxo |
| Get Many | Operação da API do n8n que retorna vários registros (todos os workflows) |
| Nó IF | Nó divisor que separa o fluxo em caminho verdadeiro e falso |
| Convert to File / Convert to JSON | Operação que transforma dados em arquivo (aqui, JSON), um por item |
| Base URL | Endereço da API do n8n no formato `endereco/api/v1` |
| API Key | Chave de acesso à API do n8n; deve ser sem expiração para o backup e mantida secreta |
| Import from File | Recurso do n8n (menu de três pontos) que restaura um workflow a partir de um JSON |
| Subpasta datada | Pasta criada por execução, nomeada com data/hora únicas |
