# 19. Deixar a Secao Editavel no Computador e no Celular

> Pega um pedaço do tema que só se muda no código e transforma numa seção completa, com ajustes separados para computador e para celular, tudo pelo editor.

## O que você precisa ter antes

- Node 20 ou mais novo. Os scripts do motor não têm dependência externa, não acessam rede e não pedem login: não há `npm install` a fazer.
- O tema baixado na máquina e o Shopify CLI autenticado para conferir e mandar de volta.
- Uma cópia não publicada do tema para trabalhar. Nada vai para o tema ao vivo antes de você olhar.
- O arquivo de origem em mãos: pode ser um snippet, um bloco de código colado no editor ou uma seção antiga sem ajuste de celular.

## O que ela faz

Converte três tipos de origem em uma seção de verdade:

| Origem | O que era |
|---|---|
| `snippets/x.liquid` | um pedaço chamado por `{% render 'x' %}`, sem nenhum controle no editor |
| bloco de código colado | um "custom liquid" enfiado dentro de outra seção pelo editor |
| seção antiga | seção que existe mas serve o mesmo valor para as duas telas |

O resultado tem sempre a mesma forma. Todo valor que estava escrito no código (cor, medida, texto) vira um ajuste no schema com aquele valor como padrão. Os ajustes ficam em dois grupos separados: um cabeçalho "Desktop" com os `desktop_*` embaixo e um cabeçalho "Mobile" com os `mobile_*`. O CSS não repete nada: ele lê variáveis, e uma media query em 749px troca só os valores.

**Seção com um único bloco de ajustes servindo as duas telas não passa.** Quem cobra isso é o `checar-mobile.mjs` do motor, no passo 5: ele lê o schema, exige o par de cada ajuste e os dois cabeçalhos de grupo, e sai com erro listando o que falta. Quatro seções deste mesmo pacote são anteriores ao gate e reprovam nele hoje: as três prontas da skill 10 e a janela da skill 107. Rode o gate nelas antes de publicar e você vê exatamente o que falta em cada uma.

Os sete pares que sempre existem: espaçamento em cima, espaçamento embaixo, número de colunas, espaço entre itens, tamanho da fonte, altura da imagem e alinhamento do texto. Mais um par de "mostrar nesta tela", que permite esconder a seção só no celular ou só no computador.

Os textos dos rótulos nascem em chaves de tradução (`t:`), com o arquivo de idioma populado junto. Isso é o que permite a loja falar outro idioma depois sem refazer a seção.

Existe ainda um caso opcional: quando a loja atende um país que herda o idioma principal sem ter idioma próprio, dá para criar campos de troca por país (`heading_gb` ao lado de `heading`, por exemplo) e o Liquid escolhe pelo país do visitante. Só use isso quando o país realmente não tem idioma próprio habilitado. Se tem, a tradução normal é mais limpa.

## Como usar

### Passo 1. Ler o arquivo de origem

Separe quatro coisas: os valores escritos no código (viram padrões dos ajustes), as variáveis dinâmicas como `{{ product.title }}` (viram lógica), os SVGs embutidos (ficam como estão) e o texto (vira ajuste de texto).

### Passo 2. Descobrir o que muda entre as telas

Para cada medida que o CSS original trocava numa media query, crie o par `desktop_X` e `mobile_X`. Se o original só tinha valor de computador, o valor de celular começa em torno de 60% dele, que é um ponto de partida saudável.

### Passo 3. Escrever o `.liquid`

O markup, o CSS com variáveis e a media query de 749px, e o schema com os dois grupos. Duas coisas que costumam passar batido:

- A classe do elemento raiz leva o prefixo da sua própria seção. Não reaproveite prefixo de exemplo, senão o CSS de uma seção vaza na outra.
- `presets` com pelo menos um item. Sem isso a seção não aparece na lista de adicionar.

O esqueleto do CSS é sempre este:

```liquid
<style>
  #section-{{ section.id }} {
    --pad-top: {{ section.settings.desktop_padding_top }}px;
    --cols: {{ section.settings.desktop_columns }};
    --gap: {{ section.settings.desktop_gap }}px;
    --fs: {{ section.settings.desktop_font_size }}px;
  }
  @media (max-width: 749px) {
    #section-{{ section.id }} {
      --pad-top: {{ section.settings.mobile_padding_top }}px;
      --cols: {{ section.settings.mobile_columns }};
      --gap: {{ section.settings.mobile_gap }}px;
      --fs: {{ section.settings.mobile_font_size }}px;
    }
  }
  #section-{{ section.id }} .grid {
    display: grid;
    grid-template-columns: repeat(var(--cols), 1fr);
    gap: var(--gap);
  }
</style>
```

### Passo 4. Popular o arquivo de idioma

Este é o passo do motor. Ele lê o schema que você acabou de escrever, extrai todas as chaves `t:sections.{slug}.*` e escreve as entradas no arquivo de idioma. O merge nunca sobrescreve texto que você já ajustou à mão.

```bash
cd "_engine/refatorar-section"

# ver o que seria mudado, sem gravar
node gen-locale.mjs --dry-run \
  --section /caminho/do/tema/sections/promise.liquid \
  --locale-file /caminho/do/tema/locales/en.default.schema.json

# gravar
node gen-locale.mjs \
  --section /caminho/do/tema/sections/promise.liquid \
  --locale-file /caminho/do/tema/locales/en.default.schema.json
```

Se a seção já existe com os rótulos escritos direto no schema, o migrador troca cada rótulo por uma chave e leva o texto para o arquivo de idioma, preservando CSS, blocos e presets:

```bash
node migrator-v1-to-v2.mjs \
  --section /caminho/do/tema/sections/promise.liquid \
  --locale-file /caminho/do/tema/locales/en.default.schema.json --dry-run
```

O texto inicial de cada entrada é rascunho, gerado a partir do id do ajuste: `desktop_padding_top` vira "Desktop Padding Top". Reescrever depois é esperado, e o merge nunca desfaz o que você escreveu.

### Passo 5. Conferir

```bash
cd "_engine/refatorar-section"
node checar-mobile.mjs --section /caminho/do/tema/sections/promise.liquid

shopify theme check --path /caminho/do/tema
```

O primeiro comando é o gate do par desktop/mobile: ele reprova quando um ajuste ficou sem par ou quando faltam os cabeçalhos "Desktop" e "Mobile". O segundo é o lint do Liquid. Corrija tudo antes de mandar. Depois, na cópia do tema, abra o editor e confirme que a seção aparece na lista, que os ajustes estão em dois grupos separados e que os rótulos aparecem legíveis, não como chave.

### Passo 6. Tirar a origem de circulação

| Origem | O que fazer |
|---|---|
| snippet | remover o `{% render 'x' %}` de quem chamava e acrescentar a seção nova nos templates JSON, no array `sections` e no `order` |
| seção antiga | substituir o arquivo e remapear os ajustes já salvos nos templates (`padding_top` passa a ser `desktop_padding_top`) |
| bloco de código colado | remover o bloco do template JSON e acrescentar a seção como seção própria |

Manter a origem viva em paralelo confunde: duas coisas parecidas na lista do editor e ninguém sabe qual está no ar.

## O que ela devolve

- O arquivo `sections/{nome}.liquid` completo: markup, CSS com variáveis, media query de 749px e schema com os dois grupos e os presets, aprovado no `checar-mobile.mjs`.
- O `locales/en.default.schema.json` com todas as chaves do schema populadas.
- Os templates JSON alterados para usar a seção nova no lugar da origem.
- Uma seção que você configura inteira pelo editor, inclusive para esconder no celular sem mexer em código.

## Onde erra

**Os scripts não escrevem a seção.** Eles conferem o schema e mexem em rótulo e arquivo de idioma, e só. O `.liquid` (markup, CSS, media query, os dois grupos do schema) continua sendo escrito à mão seguindo o modelo acima. Quem espera que `gen-locale.mjs` gere a seção fica esperando.

**A flag `--slug` não existe.** O `checar-mobile.mjs` aceita só `--section`; o `gen-locale.mjs` e o `migrator-v1-to-v2.mjs` aceitam apenas `--section`, `--locale-file` e `--dry-run`. O slug sai sempre do nome do arquivo `.liquid`. Passar `--slug` derruba o comando.

**O editor mostra `t:sections.x.name` em vez do nome.** O schema tem as chaves e o arquivo de idioma não foi populado. É o passo 4 que resolve. Se já rodou e continua, compare a chave do schema com a entrada do arquivo caractere por caractere: maiúscula e ponto contam.

**A seção não aparece para adicionar.** Faltou `presets`.

**Os ajustes aparecem numa lista só, sem separação.** Faltou o `{"type": "header"}` antes de cada grupo. O editor não agrupa sozinho por prefixo.

**Ajuste de intervalo recusado em silêncio.** A Shopify limita o intervalo a 101 passos. `min:0 max:200 step:1` são 201 passos, e o schema inteiro deixa de carregar. Suba o `step` para 2.

**A classe do exemplo vai para produção.** O modelo de markup traz uma classe de exemplo no elemento raiz. Trocar pelo prefixo da sua seção é obrigatório: duas seções com a mesma classe compartilham CSS e uma quebra a outra.

**As variáveis não atualizam no preview do editor.** O editor guarda cache forte. Recarregue com cache limpo ou abra numa janela anônima antes de concluir que o CSS está errado.

**A troca por país não aplica.** O país do visitante vem vazio ou diferente do esperado. Confirme que aquele país existe como mercado na loja e teste forçando o país na URL do produto antes de mexer no Liquid.

**A seção perde os ajustes depois do envio.** Aconteceu envio em lote e um arquivo não subiu, mesmo com o CLI dizendo sucesso. Leia o arquivo de volta da loja para confirmar, e prefira mandar um arquivo por vez.
