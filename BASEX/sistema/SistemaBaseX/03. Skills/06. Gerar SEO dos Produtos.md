# Gerar SEO dos Produtos

> Escreve meta title, meta descrição, descrição em HTML, tags e tipo de produto para o catálogo inteiro, preenche a categoria da Shopify, o alt text das imagens e publica nos canais de venda que a sua loja tem.

## O que você precisa ter antes

- Shopify CLI instalado (`npm i -g @shopify/cli`) e a sua loja autenticada.
- Escopos `read_products,write_products,read_files,write_files,read_publications,write_publications,read_online_store_navigation,write_online_store_navigation` na autenticação, exatamente os do comando abaixo. Os de navegação são o que permite criar o redirecionamento 301 quando um título muda e leva o endereço junto.
- O catálogo já no idioma em que a loja vende. Esta skill escreve SEO, ela não traduz. Se o catálogo ainda está em outro idioma, [[05. Traduzir os Produtos]] vem antes.
- O nome da marca que a loja usa hoje, e o nome antigo se houve troca de marca.
- Nada de Node ou Python: o trabalho todo é feito pela CLI da Shopify e pela leitura do catálogo.

```bash
shopify store auth --store sualoja.myshopify.com \
  --scopes "read_products,write_products,read_files,write_files,read_publications,write_publications,read_online_store_navigation,write_online_store_navigation"
```

## O que ela faz

Para cada produto do catálogo:

| Campo | Regra |
|---|---|
| Meta title | 50 a 65 caracteres, palavra-chave na frente, marca no fim |
| Meta descrição | 145 a 160 caracteres, benefício concreto e chamada para ação |
| Descrição em HTML | Estrutura com H1, resumo denso no primeiro parágrafo, blocos de atributo, medidas, cuidados e garantia, mínimo de 200 palavras |
| Tags | 12 a 15, misturando termo curto, cauda longa, intenção de compra e atributo |
| Tipo de produto | Categoria limpa, nunca o nome do produto e nunca a marca |
| Fornecedor | Marca atual |
| Categoria da Shopify | A folha mais específica da taxonomia que se aplica ao produto |
| Alt text | Título do produto e marca, em toda imagem |
| Política de estoque | Toda variante em "continuar vendendo sem estoque" |
| Canais | Loja Online sempre, e os demais canais que existirem na loja |

O primeiro parágrafo da descrição é escrito para ser lido inteiro e fora de contexto, porque é o trecho que assistentes de busca copiam. Ele carrega material, medida, para quem serve e o benefício principal, sem depender do resto da página.

Três conferências travam a entrega:

1. **Nenhum vestígio da marca antiga** em título, fornecedor, tipo de produto, meta title, meta descrição, descrição e endereço do produto.
2. **Tipo de produto limpo**: nada de campo vazio, nada de repetir o título do produto dentro dele, nada de marca, nada de símbolo de registro.
3. **Categoria da Shopify preenchida** em todo produto ativo.

O que fica de fora:

- O endereço do produto só muda se o título do produto mudar. Escrever meta title e meta descrição não mexe no título, então o endereço fica como está. Quando o título mudar, o endereço é regerado e o redirecionamento 301 é criado na mesma operação.
- Traduzir vai para [[05. Traduzir os Produtos]]. Preço, marca e tamanho vão para [[03. Editar Produtos da Loja]]. Os campos do feed do Google vão para [[47. Preparar Produtos para o Google]]. Se o seu pedido couber em duas dessas, a skill pergunta antes de mexer.

## Como usar

### Passo 1: conferência de acesso e cópia de segurança

```bash
shopify store execute --store sualoja.myshopify.com --json \
  --query 'query { shop { name } publications(first: 20) { nodes { id name } } }'
```

Guarde a lista de canais que apareceu: é ela que decide onde dá para publicar no fim. Depois, o catálogo inteiro vai para um arquivo local, que é a cópia para voltar atrás:

```bash
shopify store execute --store sualoja.myshopify.com --json \
  --query 'query { products(first: 20) {
    pageInfo { hasNextPage endCursor }
    nodes { id handle title vendor productType tags status descriptionHtml
            seo { title description }
            media(first: 20) { nodes { alt ... on MediaImage { image { url } } } } } } }' \
  > seo-antes-01.json
```

Vinte por página, e não o catálogo inteiro de uma vez, porque a Shopify recusa consulta acima de 1.000 pontos e conta o custo antes de rodar: cada produto aqui já custa as vinte imagens pedidas junto. Repita trocando `products(first: 20)` por `products(first: 20, after: "<endCursor da página anterior>")`, uma página por arquivo, até `hasNextPage` vir `false`.

### Passo 2: escrever

A skill lê o arquivo e escreve, produto a produto, os campos da tabela acima. O texto sai no idioma em que a loja vende, com número e medida reais tirados do próprio produto, sem prometer prazo de entrega que a operação não controla.

### Passo 3: conferir o texto antes de aplicar

Antes da primeira escrita, a skill roda as três conferências sobre o texto novo e mostra três produtos com antes e depois lado a lado. Se algum produto reprovar, ele volta para reescrita, não vai para a loja.

### Passo 4: aplicar

Toda escrita passa pelo mesmo molde de comando. A CLI desliga mutation por padrão, então `--allow-mutations` é obrigatório, e os valores entram por um arquivo JSON apontado em `--variable-file` (singular, sem "s"):

```bash
shopify store execute --store sualoja.myshopify.com --json --allow-mutations \
  --query-file mutation.graphql --variable-file vars.json
```

Em `mutation.graphql`:

```graphql
mutation($p: ProductUpdateInput!) {
  productUpdate(product: $p) {
    product { id handle } userErrors { field message }
  }
}
```

Em `vars.json`, um produto por chamada, com `title`, `descriptionHtml`, `productType`, `vendor`, `tags` e `seo`:

```json
{ "p": { "id": "gid://shopify/Product/123", "productType": "Belt", "vendor": "Marca",
         "tags": ["leather belt", "mens belt"],
         "seo": { "title": "Leather Belt | Marca", "description": "..." } } }
```

Em lotes, com pausa entre eles por causa do limite de chamadas.

### Passo 5: categoria da Shopify

A categoria certa vem da própria taxonomia, buscada pelo tipo de produto já limpo:

```bash
shopify store execute --store sualoja.myshopify.com --json \
  --query 'query { taxonomy { categories(search: "belt", first: 10) { nodes { id fullName isLeaf } } } }'
```

Escolha o resultado com `isLeaf: true` mais específico e grave com `productUpdate`, no mesmo molde de comando do Passo 4, passando `category` com o id devolvido pela busca. Nunca invente id de categoria.

### Passo 6: imagens e alt text

Converta as imagens para WebP antes de subir, com [[15. Converter Imagens para WebP]]. Para imagem que já está na loja há tempo, trocar arquivo por arquivo rende pouco: o CDN da Shopify já entrega WebP para os navegadores que aceitam. O que vale sempre é o alt text preenchido em toda imagem, com o título do produto e a marca.

### Passo 7: estoque e canais

Toda variante fica com `inventoryPolicy: CONTINUE` via `productVariantsBulkUpdate`. Depois, os produtos ativos e as coleções são publicados nos canais que apareceram no Passo 1, com `publishablePublish`. As duas são mutations e vão no mesmo molde de comando do Passo 4, com `--allow-mutations`. Canal que a loja não tem é pulado, não é erro.

### Passo 8: coleções vazias e conferência final

Coleção sem produto é apagada. O catálogo é lido de novo e a skill só encerra com:

- todo produto ativo com meta title e meta descrição dentro do tamanho;
- zero vestígio da marca antiga em qualquer campo;
- tipo de produto e categoria preenchidos;
- toda variante em CONTINUE;
- alt text em toda imagem.

## O que ela devolve

- `seo-antes-01.json` e seguintes, uma por página lida, a cópia de segurança do catálogo.
- O catálogo atualizado na loja.
- Uma tabela por campo: quantos produtos receberam meta title, meta descrição, descrição nova, tags, tipo, categoria e alt text.
- A lista dos produtos que a skill marcou para revisão sua, com o motivo de cada um.
- A lista de canais em que os produtos foram publicados, e os que a loja não tinha.

## Onde erra

**Rodar SEO antes de traduzir.** Você paga a escrita duas vezes: o texto sai em um idioma e a tradução depois reescreve tudo por cima. A ordem é traduzir primeiro, escrever SEO depois.

**Reescrever a descrição e apagar o que o tema esperava.** Muitas lojas usam a descrição para renderizar tabela de medidas, blocos com classe própria ou dado que o app de avaliação lê. A descrição nova entra sem esses blocos e a página perde uma seção inteira. Abra uma página de produto depois da primeira leva e compare com o antes.

**Meta descrição acima de 160 caracteres.** O Google corta no meio e a frase termina em reticências. Conte caracteres, não palavras, e teste no produto de nome mais longo do catálogo.

**Deixar a marca antiga entrar no meta title.** É o campo que o Google reindexa mais rápido, e é o que aparece no anúncio. A conferência de marca antiga precisa rodar sobre o texto novo, antes da escrita, não depois.

**Escolher a categoria pela palavra do título.** Título com "capa" ou "case" casa com categoria de eletrônico, de vestuário e de papelaria. Olhe o `fullName` e o `isLeaf` do resultado da busca, não só o id.

**Aplicar o alt text antes de trocar as imagens.** A troca sobe arquivos novos e o alt volta a ficar vazio. Imagem primeiro, alt depois.

**Tentar publicar num canal que a loja não tem.** A mutation falha, o lote inteiro para e o que já foi escrito fica pela metade. Leia as publicações da loja no começo e trabalhe só com as que existem.

**Encher de tags.** Trinta tags não ranqueiam mais e viram filtro sujo no tema: as coleções automáticas passam a se sobrepor e o mesmo produto aparece em cinco lugares. Doze a quinze, escolhidas, resolvem.
