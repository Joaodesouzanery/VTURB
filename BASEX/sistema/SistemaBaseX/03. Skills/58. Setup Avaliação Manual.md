## Contexto

Instala a section **Trust Reviews** (avaliações manuais estilo Trustpilot, sem marca) em qualquer tema Shopify Online Store 2.0. A section é 1 arquivo Liquid auto-contido, zero apps, e a fonte canônica vive em `06. Anexos/trust-reviews.liquid`.

Recursos da section (v1.1, validada em tema Dawn premium, desktop 1440px e mobile 390px):
- **Multi-idioma**: EN / ES / DE / IT / FR — seletor único traduz toda a UI fixa (rótulo da nota, "Based on X reviews", "Verified Purchase", datas relativas com singular/plural e gramática nativa, botões). Textos das reviews ficam como escritos.
- **Header**: rótulo automático pela nota (Excellent/Great/...), estrelas verdes Trustpilot com preenchimento fracionário, nota e total híbridos (média automática dos blocks OU override manual) exibidos como "4.8 · Based on 2,347 reviews", logo Trustpilot opcional (SVG embutido).
- **Cards**: avatar (foto ou inicial colorida automática), nome, data relativa (número + unidade), badge verificado, nota numérica junto das estrelas (ex: 4.0), título, texto, até 3 fotos do cliente.
- **Fotos**: 2 layouts (Large photo on top — hero 1:1 estilo UGC, padrão — ou Thumbnails below text), todas clicáveis com lightbox próprio (X, Esc, clique fora, trava scroll).
- **Desktop**: carrossel com setas, dots, drag; **Mobile**: lista empilhada com botão "Show more reviews" traduzido (ou carrossel, configurável).
- **49 settings** no editor: cores, tipografia desktop/mobile separada, radius de card e foto, autoplay, larguras.

Usar quando:
- "/setup-avaliacao-manual {loja}"
- "instala a section de reviews trustpilot na {loja}"
- "coloca a section trust reviews no tema X"

Não confundir com importar reviews de produto: aquilo traz avaliação de produto pra dentro de um app de reviews. Esta skill instala a section visual de avaliações manuais, escritas por você no editor de temas, sem app e sem mensalidade.

## Inputs

Perguntar ao usuário **antes de executar** (a menos que já estejam em `$ARGUMENTS`):

### Obrigatórios
1. **Loja** - handle `.myshopify.com` da sua loja. O acesso é a sua própria conta Shopify: se o CLI ainda não estiver logado, rodar `shopify auth login --store {handle}` (abre o navegador). Sem navegador, gerar um token no app Theme Access da própria loja.
2. **Tema alvo** - ID ou nome. Listar os temas da loja e apresentar. Se o usuário apontar o tema LIVE, avisar e exigir confirmação explícita (gate da regra shopify-theme-safety).

### Opcionais
- **Idioma** da section (default: idioma principal da loja; a section suporta en/es/de/it/fr)
- **Inserir na PDP?** (default: não — orientar a adição pelo editor: Add section > "Trust Reviews")

## Passos de execução

### Passo 0 - Pre-flight

```bash
node "_engine/setup-avaliacao-manual/preflight.mjs"
```

Valida: Node 20+, Shopify CLI no PATH, arquivo canônico existe e o `{% schema %}` parseia. Se algum check falhar, PARAR e resolver antes de seguir.

### Passo 1 - Resolver loja e credencial

1. Testar o acesso: `shopify theme list --store {handle}`. Se pedir login ou negar acesso, rodar `shopify auth login --store {handle}` e aprovar no navegador com a conta dona da loja. Sem navegador: Admin da loja > Apps > Theme Access > criar token `shptka_`.
2. Se a loja não está no índice: testar `shopify theme list --store {handle}` (auth de sessão pode cobrir). Se negar acesso, reautorizar a loja com `shopify store auth --store {handle}.myshopify.com` antes de continuar.

### Passo 2 - Resolver tema alvo (gate de segurança)

```bash
shopify theme list --store {handle} [--password shptka_...]
```

- Apresentar a lista ao usuário se o tema não veio nos inputs.
- **Se o tema alvo é o LIVE (role main): BLOQUEAR e perguntar.** Recomendar instalar primeiro num tema backup/unpublished, validar, e só depois repetir no live com autorização.

### Passo 3 - Dry-run

```bash
node "_engine/setup-avaliacao-manual/install.mjs" --store {handle} --theme {id} [--password shptka_...] --dry-run
```

Mostra o plano exato (tema, role, arquivo) sem enviar nada. Confirmar com o usuário.

### Passo 4 - Instalar

```bash
node "_engine/setup-avaliacao-manual/install.mjs" --store {handle} --theme {id} [--password shptka_...] [--allow-live]
```

O script copia a section canônica pra uma pasta temporária e faz `shopify theme push --only sections/trust-reviews.liquid --nodelete` (não toca em NENHUM outro arquivo do tema). `--allow-live` só com a confirmação do Passo 2.

### Passo 5 - Configurar (opcional)

- **Idioma**: se pedido, orientar (ou aplicar via edição do template JSON) o setting `language` da section.
- **Inserir na PDP**: se `inserir_pdp` = sim, editar `templates/product.json` do tema adicionando a section `trust-reviews` na posição desejada do `order` (padrão validado: logo após o FAQ). Caso contrário, orientar: editor de temas > página de produto > Add section > **Trust Reviews** (já vem com 3 reviews de exemplo).

### Passo 6 - Validar visualmente

Abrir `https://{handle}.myshopify.com/products/{qualquer}?preview_theme_id={id}` no Chrome (Chrome Brain), conferir desktop + mobile (section renderiza, carrossel/empilhado funciona, lightbox abre). Nunca marcar concluído sem validação visual.

### Passo 7 - Entregar

```
=== Trust Reviews instalada ===
Loja: {handle}
Tema: {nome} (#{id}, {role})
Preview: {link}
Próximo passo: editor de temas > Add section > "Trust Reviews"
Guia completo pros alunos: 05. Guias/Section Trust Reviews - Guia de Instalacao (Alunos).md
```

### Rollback

O rollback automático usa `shopify store execute` (Admin API), que **não aceita** o token Theme Access `shptka_`. Antes de contar com ele, rodar uma vez:

```bash
shopify store auth --store {handle} --scopes read_themes,write_themes
```

Se preferir não autorizar o app, o rollback manual é apagar a section pelo editor de temas: Online Store > Themes > Edit code > sections > `trust-reviews.liquid` > Delete.

```bash
node "_engine/setup-avaliacao-manual/install.mjs" --store {handle} --theme {id} --rollback
```

Remove `sections/trust-reviews.liquid` do tema via `themeFilesDelete` (Admin API). Alternativa manual: admin > tema > Edit code > deletar o arquivo. A section só existe nesse arquivo; remover o arquivo reverte 100% (se foi inserida em templates JSON, remover também a entrada do `order`).

## Troubleshooting

| Erro | Causa | Solução |
|------|-------|---------|
| `you don't have access to this dev store` | Sessão CLI logada em conta errada | Usar `--password shptka_...` do índice de credenciais, ou re-auth device-code na conta dona |
| `[BLOQUEADO] tema LIVE` | Gate de segurança do install.mjs | Confirmar com o usuário; rodar com `--allow-live` apenas após autorização explícita |
| Push falha com erro de schema | Arquivo canônico corrompido/editado à mão | Rodar preflight (valida o JSON do schema); restaurar de `06. Anexos/trust-reviews.liquid` do Obsidian Sync |
| Section não aparece no "Add section" | Tema não é Online Store 2.0 (vintage) | Tema precisa suportar sections em templates JSON; temas vintage não são suportados |
| Carrossel não inicializa no editor | Editor recarregou a section | F5 no editor resolve; na loja pública funciona sempre |
| Token `shptka_` revogado | App Theme Access desinstalada | Reinstalar o app Theme Access na loja e gerar token novo. Guardar o token no seu gerenciador de senhas, nunca dentro do SistemaBaseX |
