# Shopify Admin via Chrome Brain — Padrões Reusáveis

> Padrões testados pra dirigir o admin da Shopify via Chrome Brain quando o token do CLI não tem o scope, ou quando a operação não tem API pública. Fonte de verdade dos snippets que antes eram redescobertos toda sessão. Validado numa loja em produção em 02/08/2026.

## Quando usar cada caminho

| Operação | Caminho | Por quê |
|---|---|---|
| Markets, frete, locales, políticas | **API interna CSRF** (§1) | Usa a sessão logada do admin; ignora scopes OAuth faltando no CLI Connector |
| Timezone da loja | **UI (s-select)** (§3) | `shop.ianaTimezone` é read-only na GraphQL — só via tela |
| Adicionar/publicar idioma | **API** `shopLocaleEnable`/`shopLocaleUpdate` (§5) | Funciona headless, não precisa de app nem UI |
| Vendas, pedidos, clientes | **UI de Analytics** (§2) | Protected Customer Data bloqueia `read_orders`/`read_customers` no CLI Connector |

## 1. Helper da API interna do admin (CSRF)

O admin da Shopify expõe um proxy GraphQL interno autenticado pela sessão do browser (cookie), não pelo token OAuth. Isso permite mutations que o token do CLI Connector recusaria por falta de scope (`write_markets`, `write_shipping`, `write_locales`). Rodar via `mcp__chrome-devtools__evaluate_script` na aba do admin logado.

```javascript
async () => {
  // 1) extrair o CSRF token da página
  let token;
  try { token = JSON.parse(document.querySelector('[data-serialized-id="server-data"]').textContent).csrfToken; } catch(e){}
  if (!token) { for (const s of document.querySelectorAll('script')) { const mm = s.textContent.match(/"csrfToken":"([^"]+)"/); if (mm){token=mm[1];break;} } }

  // 2) wrapper: op = operationName, type = 'query' | 'mutation'
  const HANDLE = 'minha-loja'; // o handle da sua loja, o que vem antes de .myshopify.com
  const gql = async (op, query, variables={}, type='query') =>
    (await (await fetch(`https://admin.shopify.com/api/shopify/${HANDLE}?operation=${op}&type=${type}`, {
      method: 'POST',
      headers: {
        'Accept': 'application/json',
        'Content-Type': 'application/json',
        'X-CSRF-Token': token,
        'X-Shopify-Web-Force-Proxy': '1'
      },
      credentials: 'include',
      body: JSON.stringify({ operationName: op, query, variables })
    })).json());

  // 3) exemplo — habilitar francês (mutation)
  return gql('EnableLocale',
    'mutation EnableLocale($locale:String!){shopLocaleEnable(locale:$locale){shopLocale{locale name published}userErrors{field message}}}',
    { locale: 'fr' }, 'mutation');
}
```

Notas:
- `X-Shopify-Web-Force-Proxy: 1` + `credentials: 'include'` são obrigatórios.
- O `operation`/`type` na querystring precisam bater com o `operationName`/tipo no body.
- Casou em produção pra `marketCreate`, `deliveryProfileUpdate`, `shopLocaleEnable/Update`, e leitura de `shop`/`shopLocales`. É o cavalo de batalha de mercados+frete+idioma.

## 2. Protected Customer Data (o que NÃO dá pra ler por API)

O app **Shopify CLI Connector** NÃO tem aprovação de Protected Customer Data. Então `read_orders` e `read_customers` retornam **access denied** mesmo pedindo o scope. Consequência prática:

- Dado de **venda / pedido / cliente** (qual país vendeu mais, receita, e-mails) só sai pela **UI de Analytics** (ShopifyQL explore) ou por um **Custom App aprovado** (skill `16. Criar Custom App Shopify`).
- Não perder tempo tentando reautorizar o CLI Connector pra isso — o refresh sempre falha (rc=1). Ir direto pra UI.

## 3. Web components `s-select` / `s-internal-select` (admin novo)

O admin novo da Shopify (Polaris web components) NÃO usa mais `<select>` nativo em vários campos (timezone, região de backup, unidades). Por isso `document.querySelectorAll('select')` retorna `[]` e o `fill`/`click` no combobox falha silenciosamente. A árvore de acessibilidade mostra as opções como filhas, o que engana.

Detecção e set corretos:

```javascript
async () => {
  // achar o host a partir de uma option conhecida
  const opt = Array.from(document.querySelectorAll('*'))
    .find(e => e.tagName === 'S-OPTION' && (e.textContent||'').trim() === '(GMT+01:00) Paris');
  // opt.value = 'Europe/Paris'; o host é um <s-internal-select name="currency.timeZone">
  const sel = Array.from(document.querySelectorAll('s-internal-select'))
    .find(s => (s.getAttribute('name')||'') === 'currency.timeZone');
  sel.value = 'Europe/Paris';
  sel.querySelectorAll('s-option').forEach(o =>
    o.getAttribute('value') === 'Europe/Paris' ? o.setAttribute('selected','') : o.removeAttribute('selected'));
  sel.dispatchEvent(new Event('input', { bubbles: true }));
  sel.dispatchEvent(new Event('change', { bubbles: true }));
  return sel.value;
}
```

Depois: a barra "Alterações não salvas" aparece → clicar o botão `Salvar` (`button.click()` dispara o handler React). A barra pode demorar a sumir; **confirmar pela API** (§1) que o valor persistiu, não pela UI.

## 4. Modal de Settings volta pra última seção

Navegar pra `/settings/general` às vezes cai de volta na última seção aberta (ex: `customer_events`) porque o modal de settings é um SPA que restaura estado. Solução confiável: **abrir a URL de settings numa aba nova** (`mcp__chrome-devtools__new_page`) em vez de navegar a aba existente. A aba nova não carrega o estado velho do modal.

## 5. Idioma: API pra ligar, UI só pro que não tem API

- **Ligar + publicar idioma = API** (headless, sem app, sem UI):
  ```
  shopLocaleEnable(locale:"fr")            → cria como rascunho (published:false)
  shopLocaleUpdate(locale:"fr",{published:true}) → publica
  ```
  `ShopLocaleInput` aceita `published` e `marketWebPresenceIds`; NÃO aceita `primary`.
- **Timezone = UI** (§3) — `ianaTimezone` é read-only na API.
- **Ordem recomendada** ao adicionar idioma numa loja com conteúdo: ligar como rascunho → traduzir → publicar. Publicar antes de traduzir deixa o seletor do idioma levando a conteúdo no idioma-mestre (não quebra, mas confunde).
- **Tradução — máquina vs mão:** auto-traduzir o genérico (produto, coleção, UI, botões) via Translate & Adapt; **traduzir à mão a copy de marca** (carta de fundador, storytelling, headlines). Máquina estraga copy emocional e viola a regra anti-IA (sem travessão, sem cara-de-bot).

## §6 — Checkout: branding e trust signals sem sofrimento (v2026-08-03)

- **`checkoutBrandingUpsert` é PLUS-ONLY.** Basic/Grow → `ACCESS_DENIED` mesmo pagando. O editor visual funciona em todo plano; URL direta: `admin.shopify.com/store/{handle}/settings/checkout/editor/profiles/{PROFILE_ID}?page=checkout&context=branding` (profile via `checkoutProfiles(first:20){nodes{id isPublished}}`). Painéis: Logo (imagem/largura/alinhamento Centro), Paleta de cores, Principal, Cabeçalho.
- **Chaves dos trust signals** (conteúdo padrão do tema, grupo Alternative): `shopify.checkout.alternative_payment_method_banner.express_checkout` (→ `Pay quickly and securely with our partners`) e `...alternative_payment_method_banner.or` (→ `★★★★★ (4.9 on Trustpilot reviews)`).
- **Recurso:** `ONLINE_STORE_THEME_LOCALE_CONTENT` com gid `gid://shopify/OnlineStoreThemeLocaleContent/{THEME_ID}` — resolve por `translatableResource(resourceId:)` mesmo quando a listagem só mostra o tema publicado.
- **Idiomas extras** via `translationsRegister` (digest do `translatableContent`). **Idioma principal** é recusado pelo register → override no ARQUIVO de locale do tema (grupo raiz `"shopify"` em `locales/en.default.json`, via `themeFilesUpsert`) — e o override viaja com o tema no publish.
- Locale files têm o comentário `/* auto-generated */` igual aos templates: strip antes de `json.loads`.
- FR validado: `★★★★★ (4,9 sur les avis Trustpilot)` · `Payez rapidement et en toute sécurité avec nos partenaires`.
