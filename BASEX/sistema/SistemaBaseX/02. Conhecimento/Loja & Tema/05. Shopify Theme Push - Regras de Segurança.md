# Shopify Theme Push — Regras de Segurança

> **NON-NEGOTIABLE.** Violação desta regra apaga arquivos Liquid do tema live.
> Aprendida na prática: push de diretório parcial sem `--only` deletou seções inteiras de um tema Impact em produção, em 2026-05-11.

---

## A Regra de Ouro

**NUNCA fazer `shopify theme push` de um diretório parcial sem `--only`.**

Um push sem `--only` de um diretório incompleto **deleta** todos os arquivos do tema live que não existem localmente. O CLI interpreta "esse arquivo não está no diretório local = deve ser deletado do servidor".

---

## ✅ CORRETO — Push parcial com `--only`

```bash
# Sempre usar --only ao enviar arquivos específicos
shopify theme push \
  --store loja.myshopify.com \
  --theme THEME_ID \
  --path /tmp/tema-COMPLETO \      # ← diretório com o tema inteiro
  --allow-live \
  --only "sections/slideshow.liquid,assets/hero.jpg"
```

**Regra:** `--path` aponta para o tema **completo**. `--only` filtra o que será enviado.

---

## ❌ PROIBIDO — Push de diretório parcial

```bash
# NUNCA fazer isso!
shopify theme push \
  --path /tmp/pasta-só-com-imagens \   # ← só tem 5 arquivos
  --allow-live                          # ← vai apagar templates, sections, etc.
```

---

## Checklist Antes de Qualquer Push

- [ ] `--path` aponta para o diretório com o tema **completo**?
- [ ] Se push parcial → `--only` está especificado?
- [ ] Arquivos críticos (`layout/theme.liquid`, `templates/`, `config/`) estão no `--path`?

Se qualquer item falhar → **adicionar `--only` antes de prosseguir**.

---

## Estratégia Segura para Imagens

```bash
# ✅ CORRETO — copiar imagem para o tema completo e usar --only
cp /tmp/nova-imagem.jpg /tmp/tema-completo/assets/
shopify theme push \
  --path /tmp/tema-completo \
  --only "assets/nova-imagem.jpg" \
  --allow-live
```

**Nunca** criar diretório separado só com assets e fazer push sem `--only`.

---

## Verificação de Emergência Após Push Com Erro

Se aparecer "pushed with errors", rodar imediatamente:

```bash
TOKEN="shpat_..."
STORE="loja.myshopify.com"
THEME_ID="123456"

for FILE in "templates/index.json" "layout/theme.liquid" "sections/slideshow.liquid"; do
  STATUS=$(curl -s "https://$STORE/admin/api/2024-01/themes/$THEME_ID/assets.json?asset%5Bkey%5D=$FILE" \
    -H "X-Shopify-Access-Token: $TOKEN" | python3 -c \
    "import json,sys; d=json.load(sys.stdin); print('✅ OK' if d.get('asset') else '❌ DELETADO')")
  echo "$STATUS — $FILE"
done
```

Se `DELETADO` → restaurar com push completo do diretório correto imediatamente.

---

## Escopos REST vs CLI

| Operação | Escopo | Método |
|----------|--------|--------|
| Push Liquid/JSON | CLI auth (Partner OAuth) | `shopify theme push` |
| Upload de imagem (theme asset) | CLI auth | `shopify theme push --only` |
| Upload para Files (image_picker) | `write_files` no token REST | REST API ou CLI com scope |
| Leitura de assets | `read_themes` | REST API |

O token `shpat_...` e o CLI usam autenticações diferentes com escopos diferentes.

**Data:** 2026-05-11  
**Loja:** uma loja em produção

**Restauração:** Push completo de `/tmp/bw-impact/` (tema completo) restaurou tudo em ~2 min.
