# AULA 5: Treinamento N8N + WhatsApp | Configurar Filtros de Grupo e Origem

> Aula curta e crítica: ensina a filtrar, com nós IF no n8n, quais mensagens o fluxo de IA deve processar — separando mensagem de grupo de mensagem individual e mensagem que chega (incoming) de mensagem que sai (outgoing). É a base pra o bot não responder onde não deve e não gastar token à toa.

**Canal:** [Rhavi Criador Digital](https://criador.digital)  · **Duracao:** 00:06:34 · **Publicado:** 2026-05-19 · [Assistir](https://www.youtube.com/watch?v=odbXvhk_K4A)

## 1. Tese central

Antes de mandar qualquer mensagem pra IA, o fluxo precisa de dois filtros binários: (1) é grupo ou não é, e (2) a mensagem veio de fora (incoming) ou fomos nós que enviamos (outgoing). Filtrar grupo evita a IA responder pra todo mundo e gastar token; filtrar origem prepara o terreno pra futuramente pausar o atendimento da IA quando um humano assume. Ambos os filtros são feitos com o nó IF, porque cada decisão só tem duas saídas: verdadeiro ou falso.

## 2. Frameworks e modelos mentais

> Cada framework recebe nome, explicacao, quando aplicar e citacao verbatim com timestamp.

### 2.1 Filtro de Grupo com nó IF (booleano is grupo)

**O que e:** Um nó IF que testa se a mensagem recebida é de grupo. Como a resposta só pode ser sim ou não, usa-se IF (roteador de duas saídas), não Switch.

**Como funciona:**
1. Puxar a seta a partir do nó anterior e escolher o nó `IF`.
2. No IF, selecionar o campo `é grupo` (is grupo) da mensagem.
3. Configurar a condição como booleano `is true`: se `é grupo` for verdadeiro, sai pela saída TRUE; senão, pela saída FALSE.
4. Na saída TRUE (é grupo) ligar um nó `Do Nothing` / `No Operation` (não faça nada), para o fluxo parar ali.
5. A saída FALSE (não é grupo, ou seja, mensagem de usuário individual) segue pro resto do fluxo.

**Quando aplicar:** Sempre que o webhook do WhatsApp puder receber mensagem de grupo e você não quer que a IA responda em grupo.

**Quando NAO aplicar:** Quando o objetivo é justamente atender dentro de grupos (aí a lógica precisa ser invertida ou virar allowlist — ver Seção 8).

> "Normalmente, a gente filtra mensagem de grupo ou não é, porque em grupo chega muita mensagem e a gente não quer necessariamente ficar respondendo para todas essas mensagens, nem ficar gastando a nossa IA respondendo em grupos."
> — [00:00:24]

### 2.2 Filtro de Origem com nó IF (incoming vs outgoing)

**O que e:** Um segundo nó IF que testa se a mensagem é `incoming` (veio de outra pessoa) ou `outgoing` (fomos nós, o dono do WhatsApp, que enviamos).

**Como funciona:**
1. Novo nó `IF` (de novo binário: ou é nossa ou não é).
2. Condição: `origem` igual a `incoming` -> saída TRUE.
3. Saída FALSE é o contrário de incoming, ou seja, `outgoing` (mensagem enviada por nós).
4. Referenciar o campo via set variables com `.item` (ponto item) pra garantir que o valor certo está sendo lido mesmo se algo mudar depois.

**Quando aplicar:** Pra distinguir mensagem do cliente da mensagem do próprio operador — pré-requisito de qualquer lógica de intervenção humana.

**Quando NAO aplicar:** Não aplicável nesta aula pra pausar de fato o atendimento; aqui só se separa a origem (o pausar vem na próxima aula).

> "Então, agora, a gente precisa saber se é uma mensagem nossa. Depois de saber se é grupo ou não, a gente precisa saber se é uma mensagem que vem da gente ou se é uma mensagem que vem do usuário."
> — [00:03:26]

## 4. Heuristicas e regras

Regras-de-bolso, atalhos mentais, principios que o autor enfatiza:

- **IF pra binário, Switch pra 2-3+ opções** — se a decisão só tem sim/não, use IF; na dúvida entre 2 ou 3 caminhos, use Switch pra não dar retrabalho [00:03:51]
- **Filtrar grupo pra economizar IA/token** — IA respondendo em grupo gasta "quantidade de token danada"; corta isso na entrada [00:00:36]
- **Pinar o dado do webhook pra testar** — depois de fixar (tecla P), as mensagens ficam salvas e você não precisa reenviar mensagem no WhatsApp a cada teste [00:02:16]
- **Referenciar campos com `.item` no set variables** — garante que, se algo mudar, o fluxo continua lendo o campo certo sem editar tudo de novo [00:04:25]
- **Padronizar em inglês** — inglês não tem acento (evita problema em campos) e treina a leitura de documentação [00:05:13]

## 8. Aplicacao no nosso contexto

> Esta secao conecta o conhecimento absorvido com o projeto do bot BaseX: WhatsApp em grupos de alunos, rodando Evolution API + n8n + Claude, pra tirar dúvidas e apoiar a gestão dos grupos.

**O que isso muda na nossa operacao:**

Este é O vídeo de filtragem por grupo/origem, e ele expõe exatamente a decisão de roteamento que o bot BaseX precisa acertar antes de chamar o Claude. Mas atenção à inversão de lógica: o vídeo trata grupo como algo a **ignorar** (saída "é grupo" -> Do Nothing). No BaseX é o oposto — o bot **vive dentro dos grupos de alunos**. Então o filtro binário do vídeo (é grupo sim/não) vira, no nosso caso, uma **allowlist de grupos**:

- **Filtro de origem em grupo (JID `@g.us`):** no payload da Evolution API, mensagem de grupo vem com o `remoteJid` terminando em `@g.us` (individual termina em `@s.whatsapp.net`). O IF "é grupo" do vídeo, no BaseX, testa justamente esse sufixo pra saber se a mensagem nasceu num grupo.
- **Allowlist (whitelist) de grupos certos:** em vez de "todo grupo -> Do Nothing", o bot só continua se o `remoteJid` do grupo estiver numa lista dos JIDs autorizados (os grupos de alunos ativos). Grupo fora da lista cai no Do Nothing / No Operation, igual ao ramo TRUE da aula. Isso garante que o bot atua só nos grupos certos e não vaza pra grupos aleatórios onde o número esteja.
- **Campo `participant` (quem falou no grupo):** em grupo, além do `remoteJid` (o grupo), o payload traz `participant` com o JID de quem enviou a mensagem. É esse campo que identifica o aluno individual dentro do grupo — essencial pra personalizar resposta, logar dúvida por aluno e evitar tratar o grupo inteiro como um único interlocutor.
- **Filtro de origem incoming/outgoing:** o segundo IF do vídeo (`origem == incoming`) é o gatilho de intervenção humana no BaseX. Quando um membro da equipe responde manualmente no grupo, aquela mensagem é `outgoing` (fromMe) — sinal pra o bot recuar e deixar o humano conduzir, sem duplicar resposta.

Sequência recomendada no fluxo BaseX (espelhando os dois IFs da aula): IF é grupo (`@g.us`) -> IF grupo está na allowlist -> IF origem incoming (não é `fromMe`) -> só então segue pro Claude. Qualquer falha manda pra Do Nothing.

**Acao concreta sugerida:**
- [ ] Adaptar o IF de grupo do vídeo pra testar `remoteJid` terminando em `@g.us` no fluxo do bot BaseX
- [ ] Criar a allowlist de JIDs dos grupos de alunos e um IF/Filter que só deixa passar grupo autorizado
- [ ] Extrair e persistir o campo `participant` pra identificar o aluno dentro do grupo
- [ ] Implementar o IF de origem (incoming vs `fromMe`/outgoing) como base da futura pausa por intervenção humana
- [ ] Usar pin de dados (tecla P) com payloads reais de grupo pra testar o roteamento sem depender de mensagem ao vivo

## 11. Glossario (se aplicavel)

| Termo | Significado |
|-------|-------------|
| IF | Nó do n8n com duas saídas (true/false); roteador binário |
| Switch | Nó do n8n com múltiplas saídas; usar quando há 2, 3 ou mais caminhos |
| incoming | Mensagem que chega de outra pessoa (cliente/aluno) |
| outgoing | Mensagem enviada por nós, o dono do WhatsApp |
| Do Nothing / No Operation | Nó que encerra o ramo sem executar ação |
| Pinar (tecla P) | Fixar o dado de um nó pra reusar em testes sem reenviar mensagem |
| `.item` | Referência ao item no set variables, usada pra separar campos em colunas |
