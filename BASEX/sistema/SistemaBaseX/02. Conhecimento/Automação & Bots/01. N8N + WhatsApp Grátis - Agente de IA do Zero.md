# N8N + WhatsApp GRÁTIS: Crie seu Agente de IA sem gastar NADA!

> Tutorial passo a passo de como montar um agente de IA no WhatsApp rodando 100% local e de graça, integrando n8n, a API de WhatsApp WAHA, memória Redis e o modelo Google Gemini via Docker. Vale absorver porque é o esqueleto exato do bot de WhatsApp que estamos montando para os grupos de alunos da BaseX.

## 1. Tese central

Dá para montar um agente de IA conectado ao WhatsApp sem pagar nada e sem VPS, rodando tudo na máquina local via Docker. A stack é n8n (orquestração), WAHA (API não oficial de WhatsApp), Redis (memória de conversa) e Google Gemini (modelo de IA gratuito). O fluxo recebe a mensagem por webhook, filtra os dados, passa para um AI Agent com memória e responde de volta pelo WhatsApp.

## 2. Frameworks e modelos mentais

> O vídeo é operacional, não conceitual. O "framework" aqui é a arquitetura de fluxo do agente.

### 2.1 Pipeline do Agente de WhatsApp no n8n

**O que e:** A sequência fixa de nodes que transforma uma mensagem recebida no WhatsApp em uma resposta gerada por IA.

**Como funciona:**
1. **Webhook (trigger)** recebe o evento que o WAHA dispara a cada mensagem (método POST, path `webhook`).
2. **Set (renomeado "dados")** filtra do payload bruto só os campos úteis: session, chatId, pushName, payloadId, event, message, fromMe.
3. **Switch** cria rotas por tipo de evento. Por enquanto só trata `event == message`.
4. **AI Agent** recebe a mensagem como Prompt, com System Message (instruções), Chat Model (Gemini) e Memory (Redis).
5. **WAHA "Send Seen"** marca a mensagem como visualizada (usa session, chatId, messageId).
6. **WAHA "Send a Text Message"** responde com o Output do AI Agent.

**Quando aplicar:** Protótipo ou automação de WhatsApp de baixo volume, uso pessoal ou teste, quando não se quer pagar VPS nem API oficial.

**Quando NAO aplicar:** Quando precisa que sistemas externos (outros softwares) enviem webhooks para o n8n. Rodando em rede local isso não funciona (ver Seção 7).

## 4. Heuristicas e regras

Regras-de-bolso e parâmetros que o autor enfatiza:

- **Path do webhook tem que bater exatamente** com a URL do webhook global configurada no Docker Compose do WAHA (por isso ele digita `webhook`). [00:03:54]
- **No WAHA, deixe só o evento `message`** selecionado (desmarque o primeiro) e clique em Update, senão o webhook dispara em eventos que você não quer tratar. [00:04:19]
- **Teste sempre a partir de OUTRO número.** Mandar mensagem para o próprio número da sessão não funciona. [00:04:29]
- **pushName correto vem de dentro de `_data`**, não do campo dentro de `Me` (esse é o seu próprio nome). [00:05:33]
- **Session ID do Redis puxa do node "dados", não do Switch.** A Key da memória é o chatId. [00:09:00]
- **Use Gemini 2.0 Flash, não o 1.0 Pro.** [00:08:00]
- **Baixe a Sampling Temperature** (0.2 / 0.1) se a IA estiver "muito maluca". Padrão 0.4. [00:08:12]
- **host.docker.internal** é o host correto para Redis e WAHA quando os nodes rodam dentro do Docker (não `localhost`). [00:08:44]
- **TTL da memória em segundos:** 1 hora = 3600. [00:09:15]

## 7. Contra-argumentos e nuances

- **Limitação da rede local:** por rodar na rede local do computador, outros programas e softwares externos não conseguem enviar webhooks para o seu n8n. Essa instalação serve só para automação de WhatsApp via WAHA, nada além. [00:11:43]
- **Workaround citado:** dá para contornar isso com um programa chamado Ngrok, mas o autor diz que "é assunto para outro vídeo". [00:12:04]
- **Sem delay de digitação:** como não há tempo de espera configurado, o bot responde instantaneamente, o que denuncia que é um bot (sem simulação de "digitando"). [00:11:20]
- **WAHA é API não oficial de WhatsApp**, o que implica risco de bloqueio de número (o autor não aprofunda esse ponto no vídeo).

## 8. Aplicacao no nosso contexto

> Conecta com o bot de WhatsApp que estamos montando para os grupos de alunos da BaseX (mentoria de dropshipping): stack Evolution API + n8n + Claude, que responde dúvidas com o conhecimento do curso E gera relatórios de gestão.

**O que isso muda na nossa operacao:**
Este vídeo entrega o esqueleto do fluxo n8n que vamos reusar quase 1:1. A arquitetura Webhook > Set (filtrar dados) > Switch (rotear por tipo de evento) > AI Agent > responder é exatamente o pipeline do nosso bot. Trocamos três peças pela nossa stack: WAHA vira Evolution API (o próprio autor cita Evolution como alternativa no curso, [00:12:22]); Gemini vira Claude no Chat Model; e o System Message simples vira o system prompt com o conhecimento do curso BaseX. O node Set "dados" (session, chatId, pushName, payloadId, message, fromMe) é o mesmo contrato de campos que a Evolution API entrega, então o mapeamento é direto. O `fromMe` é crítico para nós: filtra mensagens enviadas pelo próprio número do bot e evita loop de auto-resposta em grupo. O Redis Chat Memory com Key = chatId e Context Window de 10 mensagens é o ponto de partida da memória por aluno (ou por grupo), e o TTL (aqui 3600s) é o parâmetro que vamos calibrar para conversas de mentoria mais longas.

Para a metade de "relatórios de gestão" (top dúvidas da semana, performance do time de entrega, gaps de aula), o vídeo não cobre, mas mostra onde plugar: o mesmo Switch que hoje só roteia `event == message` é o lugar de adicionar rotas novas (o autor diz "no futuro podemos tratar outros tipos de eventos", [00:06:16]). Cada mensagem que passa pelo node "dados" já carrega chatId + pushName + message, que é matéria-prima para logar num banco (Postgres, que já vem de bônus no compose) e depois agregar as dúvidas por semana.

**Acao concreta sugerida:**
- [ ] Clonar este fluxo no n8n trocando WAHA por Evolution API e Gemini por Claude no Chat Model.
- [ ] Manter o node Set "dados" com o campo `fromMe` para bloquear auto-resposta do bot em grupo.
- [ ] Adicionar uma rota extra no Switch para logar toda mensagem no Postgres (chatId, pushName, message, timestamp), alimentando os relatórios de gestão.
- [ ] Definir o System Message com o conhecimento do curso BaseX e calibrar Temperature (começar em 0.2 para menos alucinação em respostas técnicas de dropshipping).
- [ ] Ajustar TTL do Redis e Context Window para conversas de mentoria (10 mensagens pode ser pouco para dúvida longa).
- [ ] Como vamos rodar em produção (grupos reais), planejar VPS em vez de rede local, já que a limitação de webhook local ([00:11:43]) inviabiliza integrações externas.
