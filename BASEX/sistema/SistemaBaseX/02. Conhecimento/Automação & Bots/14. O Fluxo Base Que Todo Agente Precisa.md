# O Fluxo Base Que Todo Agente Precisa (Curso N8N Completo)

> Monta no n8n o fluxo base de atendimento WhatsApp (webhook recebendo mensagem da Evolution/Avisa API + no de Set para organizar variaveis) que vira alicerce replicavel para varios agentes.

**Canal:** [Rhavi Criador Digital](https://criador.digital) · **Duracao:** 00:26:40 · **Publicado:** 2026-04-20 · [Assistir](https://www.youtube.com/watch?v=uRr4ALSJLRE)

---

## 1. Tese central

Todo agente de WhatsApp no n8n comeca pelo mesmo esqueleto: um webhook (metodo POST) que recebe as mensagens da API de WhatsApp e um no de Set que organiza os dados brutos em variaveis limpas (nome, numero de quem enviou, chave de API). O autor argumenta que dominar essa base replicavel primeiro, antes de qualquer IA, e o que permite montar "varios agentes" depois. O objetivo declarado e unir simplicidade de iniciante com robustez de producao: "conseguir fazer da forma mais simples possivel, mas mais profissional possivel tambem" [00:05:03].

## 2. Frameworks e modelos mentais

> Cada framework recebe nome, explicacao, quando aplicar e citacao verbatim com timestamp.

### 2.1 Fluxo Base Replicavel (alicerce -> fluxo master bot)

**O que e:** Um workflow enxuto (webhook + normalizacao de variaveis) construido uma vez e reaproveitado como ponto de partida de cada novo agente de atendimento.

**Como funciona:**
1. Cria o workflow, nomeia ("fluxo base") e adiciona tag de organizacao [00:00:31]
2. Adiciona o no webhook como primeiro no, recebendo mensagens do WhatsApp [00:00:53]
3. Adiciona no de Set para organizar variaveis e padronizar nomes [00:13:01]
4. Salva como base; no futuro clona essa estrutura para virar o "fluxo master bot" [00:26:15]

**Quando aplicar:** Sempre que for iniciar um novo bot/agente de WhatsApp no n8n; comeca do fluxo base em vez de do zero.

**Quando NAO aplicar:** Nao coberto no video (a aula so constroi ate a camada de normalizacao; agente de IA e mencionado como etapa futura, nao montado).

> "Agora, a gente vai criar o nosso primeiro fluxo de atendimento para o WhatsApp. Entao, ele vai servir de fluxo base para a gente poder replicar em diferentes agentes."
> — [00:00:13]

### 2.2 Estrutura de tres colunas do n8n (Input -> Transformacao -> Output)

**O que e:** Modelo mental de que todo no do n8n tem sempre tres colunas: dados que entram, transformacao e dados que saem.

**Como funciona:**
1. Coluna de Input (esquerda): dados que chegam do no anterior
2. Coluna de Transformacao (centro): onde voce mapeia/edita
3. Coluna de Output (direita): resultado que segue para o proximo no

**Quando aplicar:** Ao ler qualquer no e depurar de onde vem/para onde vai cada variavel.

**Quando NAO aplicar:** Nao aplicavel — regra estrutural universal do n8n segundo o autor.

> "A gente tem a coluna de Input, que e desse lado. A coluna de Transformacao dos Dados. E a gente tem a coluna de Output. [...] Tres colunas no N8N. Sempre."
> — [00:12:48]

### 2.3 Modos de resposta do webhook

**O que e:** Tres formas do webhook devolver resposta a quem o chamou.

**Como funciona:**
1. Respond immediately: devolve 200 OK na hora, sem esperar o fluxo [00:07:55]
2. When last node finishes: responde com o conteudo do ultimo no quando o fluxo termina [00:06:56]
3. Respond to webhook node: um no especifico responde em qualquer ponto do fluxo [00:06:37]

**Quando aplicar:** Escolher "respond immediately" quando a API (Evolution) so precisa saber que recebeu; escolher os outros quando precisa devolver um output especifico.

**Quando NAO aplicar:** "When last node finishes" / "respond to webhook" quando a API nao exige resposta com corpo (caso da Evolution).

> "A Evolution nao precisa de uma resposta especifica. Ela so precisa saber se esta realmente recebendo ou nao."
> — [00:08:02]

### 2.4 Manual mapping vs JSON no no de Set

**O que e:** Duas formas de setar variaveis no no Edit Fields (Set): campo a campo (manual) ou colando um JSON.

**Como funciona:**
1. Manual mapping: puxa cada campo do webhook e nomeia (usado com a Evolution) [00:14:05]
2. JSON: quando a API entrega um bloco (ex.: `JSON data` da Avisa) que precisa de parse para virar JSON estruturado [00:20:59]

**Quando aplicar:** Manual para poucos campos; JSON/parse quando os dados chegam empacotados numa string JSON.

**Quando NAO aplicar:** Nao aplicavel — sao complementares, o autor ensina os dois.

> "A gente esta recebendo o JSON data, entao a gente precisa fazer o parse desse JSON, ou seja, transformar esse JSON em um JSON estruturado separadinho."
> — [00:22:39]

## 4. Heuristicas e regras

Regras-de-bolso, atalhos mentais, principios que o autor enfatiza:

- **Sempre escolher POST no webhook de recebimento** — o mais usado; a acao do webhook e enviar informacao (a Evolution empurra evento), o n8n so recebe [00:02:46]
- **Nao esquecer o Save** — "Muita gente esquece de apertar o Save. E perguntando: por que nao esta funcionando?" [00:12:11]
- **Renomear os nos, sem espacos e sem acento** — espaco quebra referencia mais a frente; o autor usa maiuscula para bater o olho [00:13:33]
- **Atencao a maiuscula/minuscula nas expressoes** — "qualquer virgula, qualquer letra maiuscula, minuscula, vai fazer a diferenca" ao referenciar campos [00:24:16]
- **Colocar autenticacao no webhook quando for producao** — evita que "as pessoas hackeiem os seus fluxos" [00:05:42]
- **Usar API comercial (Avisa) para nao ter dor de cabeca; Evolution so com conhecimento e backup** — Evolution "de graca entre aspas" exige VPS (~R$20/mes) e manutencao, risco em producao para iniciante [00:03:56]
- **Carta na manga: se nao souber a expressao, pede pronta ao ChatGPT com print** — foi como o autor usava split antes de decorar [00:18:53]

## 6. Exemplos praticos mencionados

Casos reais, numeros, historias que o autor compartilha:

### Exemplo 1: Conexao da instancia Evolution via QR Code
Cria instancia provisoria na Evolution (via EasyPanel + dominio Cloudflare "evo-d21d"), gera a API key da instancia, faz Get QR Code, escaneia no WhatsApp (tres pontinhos > Dispositivos Conectados > Conectar Dispositivo) e conecta o numero. Depois ativa o webhook em Eventos > Webhook, cola o link do n8n, marca Base64 e o evento message.upsert, e salva.
[00:08:45]

### Exemplo 2: Limpeza do GID com split
O sender chega como `numero@s.whatsapp.net`. Aplica `.split('@')` para quebrar em array e indexa `[0]` para manter so o numero. Com aspas simples vazias, o split quebraria caractere por caractere; o separador correto e o `@`.
[00:20:00]

### Exemplo 3: Parse do JSON data da Avisa API
Na Avisa API os dados chegam empacotados em `JSON data`. Cria no Set chamado "parse", seleciona modo JSON, arrasta o `JSON data` para dentro e o output sai estruturado e separado, permitindo referenciar cada campo. Depois puxa a API key de `body.token` referenciando o no Webhook via `$(...).item.json.body.token`.
[00:20:59]

### Exemplo 4: Comparativo de custo das APIs
Zapster e ZAPI (comerciais famosas) custam ~R$100/mes. Evolution e "de graca" mas exige VPS ~R$20/mes mais manutencao. Vale a Evolution proprio quando ha ~50 clientes e conhecimento/backup; senao, API comercial que se vira se cair. Avisa API escolhida por ser parceira da comunidade e mais barata.
[00:03:44]

## 8. Aplicacao no nosso contexto

> Esta secao conecta o conhecimento absorvido com o projeto do bot BaseX (WhatsApp em grupos de alunos; Evolution API + n8n + Claude; para duvidas + gestao).

**O que isso muda na nossa operacao:**
O video entrega exatamente a camada 1 do bot BaseX: o trigger e a normalizacao. O padrao base que devemos reusar, extraido do que foi construido:

1. **Trigger** — no Webhook em POST recebe os eventos da Evolution API (evento `message.upsert`, Base64 ligado para anexos). E o ponto de entrada de toda mensagem de aluno.
2. **Normalizacao (no de Set)** — padroniza as variaveis logo na entrada, com nomes proprios nossos (nao os da API): `sender` (numero limpo via `.split('@')[0]`), `push_name` (nome do aluno), `api_key`/`token` (para responder pela mesma instancia). Isso desacopla o resto do fluxo do formato bruto da API.
3. **Agente (a acoplar)** — o video reserva o meio do fluxo para "uma IA aqui no meio" [00:06:46]; e onde entra o Claude do bot BaseX (roteando duvida vs gestao). Nao foi construido na aula, entao nao ha detalhe de memoria/prompt a copiar daqui.
4. **Resposta** — o video usa "respond immediately" (200 OK) porque a Evolution nao exige corpo; para responder o aluno de fato, a resposta do agente sai por um no de envio separado (chamando a API com o `token` salvo), nao pela resposta do webhook.

Ponto de atencao para grupos: o video trata mensagem 1:1; o `sender`/GID em grupo e o payload de grupo tem estrutura propria que a aula nao cobre. Validar o formato do `message.upsert` de grupo antes de assumir os mesmos campos.

**Acao concreta sugerida:**
- [ ] Clonar esse fluxo base (Webhook POST + Set de normalizacao) como template inicial do bot BaseX no n8n
- [ ] Padronizar as variaveis de entrada do bot: `sender`, `push_name`, `api_key`, com o split do GID por `@`
- [ ] Testar o payload real de mensagem de GRUPO da Evolution (nao coberto no video) e ajustar os campos do Set
- [ ] Definir a camada de resposta: no de envio separado usando o `token`, em vez de responder pelo webhook

## 11. Glossario (se aplicavel)

| Termo | Significado |
|-------|-------------|
| Webhook | Link que recebe (ou dispara) dados quando acionado; primeiro no do fluxo |
| Evolution API | API de WhatsApp open-source auto-hospedada (VPS), "de graca" mas com custo/manutencao |
| Avisa API | API de WhatsApp comercial parceira da comunidade, mais barata que Zapster/ZAPI |
| message.upsert | Evento da Evolution disparado a cada nova mensagem |
| GID | Codigo unico do WhatsApp no formato `numero@s.whatsapp.net` |
| String | Uma linha de texto |
| Array | Lista (de linhas de texto), resultado de um split |
| Split | Funcao que quebra uma string em array por um separador |
| Parse (JSON) | Transformar uma string JSON empacotada em JSON estruturado |
| No de Set / Edit Fields | No do n8n que guarda e renomeia variaveis (antigo "Set") |
| `$json` | Referencia ao no imediatamente anterior |
| `$(...)item.json` | Referencia a um no nomeado especifico, anterior no fluxo |
