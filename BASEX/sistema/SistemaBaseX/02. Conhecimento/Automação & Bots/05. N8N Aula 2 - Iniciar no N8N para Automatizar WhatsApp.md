# Como iniciar no N8N para Automatizar o WhatsApp | Curso de Agentes (Aula 2)

> Aula 2 do curso de agentes: ensina a tratar o JSON cru que chega do webhook do WhatsApp, normalizar os campos importantes (nome, numero, mensagem, is group) e rotear o fluxo com um node IF que separa mensagens de grupo das pessoais.

**Canal:** [Rhavi Criador Digital](https://criador.digital)  · **Duracao:** 00:13:12 · **Publicado:** 2025-03-29 · [Assistir](https://www.youtube.com/watch?v=lz_rbv7hIVc)

## 1. Tese central

Depois de conectar o webhook a uma API de WhatsApp (aula anterior), o dado chega em JSON e precisa ser tratado antes de virar automacao util. A aula mostra o segundo passo de um fluxo de agente no N8N: usar o modulo Edit Fields (Data Transformation) para transformar o JSON em objetos e salvar variaveis padronizadas, e depois usar um node IF para separar mensagens de grupo das pessoais. O objetivo declarado e dominar o inicio e o fim do fluxo, deixando o meio (prompt, criacao de agentes) para aulas seguintes.

## 2. Frameworks e modelos mentais

> Cada framework recebe nome, explicacao, quando aplicar e citacao verbatim com timestamp.

### 2.1 Loop "coloca modulo, testa, recebe, passa adiante"

**O que e:** o metodo de construir um fluxo N8N incrementalmente, um node por vez.

**Como funciona:**
1. Coloca o primeiro modulo
2. Testa e recebe o dado
3. Coloca o segundo modulo, testa
4. Vai passando a informacao de um modulo para o outro

**Quando aplicar:** em toda montagem de fluxo N8N, para validar cada etapa antes de encadear a proxima.

**Quando NAO aplicar:** nao aplicavel dentro do escopo do video (o autor apresenta como padrao universal do N8N).

> "Assim que funciona o N2N. Voce sempre coloca o primeiro modulo. Testa. Recebe. Coloca o segundo. Testa. E vai passando a informacao de um modulo para o outro."
> — [00:02:12]

### 2.2 Normalizacao de dados (manual mapping)

**O que e:** usar um segundo Edit Fields em modo manual mapping para extrair do JSON so os campos importantes e salva-los como variaveis nomeadas e padronizadas.

**Como funciona:**
1. Adiciona um Edit Fields e renomeia (o autor usa "NORM")
2. Troca o modo de JSON para manual mapping
3. Cria um campo por variavel: nome, numero, mensagem, is group
4. Define o tipo (quase sempre string) e puxa o valor do objeto de origem

**Quando aplicar:** logo apos parsear o JSON cru, para deixar o resto do fluxo trabalhando com nomes claros.

**Quando NAO aplicar:** nao aplicavel citado; o autor trata como etapa sempre desejavel.

> "Agora a gente vai utilizar o mesmo modulo para criar variaveis, para salvar variaveis. (...) E ai a gente vai criar uma coisa que se chama normalizacao."
> — [00:03:24]

### 2.3 Roteamento condicional com node IF

**O que e:** usar um modulo de flow (IF) para bifurcar o fluxo com base em uma condicao booleana, no caso is group true ou false.

**Como funciona:**
1. Adiciona o node IF apos a normalizacao (executar a normalizacao primeiro)
2. Puxa o campo is group como condicao (is group == true)
3. Ramo true: mensagem de grupo, vai para um modulo "no operation / nao faca nada"
4. Ramo false: mensagem pessoal, segue para o proximo passo (OpenAI, depois HTTP request de volta)

**Quando aplicar:** para tratar so as mensagens pessoais por enquanto e ignorar as de grupo.

**Quando NAO aplicar:** o proprio autor diz que ignorar grupo e "por enquanto"; quando o objetivo for atender grupos, o ramo muda.

> "Entao, se for grupo e ele for true, essa condicao aqui vai ser true tambem. (...) Porque a gente quer tratar so as mensagens pessoais por enquanto."
> — [00:09:44]

## 7. Contra-argumentos e nuances

Pontos onde o autor reconhece limites, excecoes ou contradicoes do proprio framework:

- Ignorar grupos e provisorio: "Porque a gente quer tratar so as mensagens pessoais por enquanto" [00:10:07]. O tratamento de grupo pode ser adicionado depois.
- O passo de parsing do JSON so existe para a Avisa App; com Evolution ele e desnecessario porque o dado ja vem estruturado [00:03:06].
- Mensagem de grupo pode chegar sem texto (reacao/evento), entao "nao tem mensagem" e um caso esperado a tratar [00:11:44].
- O meio do fluxo (prompt, agente) fica fora do escopo desta aula, tratado como "trabalho infinito" para aulas especificas [00:13:07].

## 8. Aplicacao no nosso contexto

> Esta secao conecta o conhecimento absorvido com o projeto do bot BaseX de WhatsApp (grupos de alunos; Evolution API + n8n + Claude; responder duvidas + gestao).

**O que isso muda na nossa operacao:**
O bot BaseX roda em Evolution API + n8n, entao o passo de parsing do JSON cru da aula (Edit Fields modo JSON) pode ser pulado: a Evolution ja entrega o payload estruturado, como o proprio autor diz. O que continua valioso e o node de normalizacao (Edit Fields manual mapping) para padronizar nome, numero, mensagem e is group antes de mandar pro Claude, e o split do GID para extrair o numero limpo (numero + @s.whatsapp vira so o numero via indice [0] do split no @). Ponto de atencao importante: o video roteia is group true para "nao faca nada" porque so quer mensagens pessoais. No bot BaseX e o oposto, o publico sao grupos de alunos, entao a ramificacao do IF deve inverter (tratar is group true, ou desligar esse filtro) e ainda lidar com o caso de evento de grupo sem texto (reacao), que precisa ser descartado antes de chamar o Claude. O fechamento do fluxo, HTTP request devolvendo a resposta ao WhatsApp, e exatamente a arquitetura do bot; troque o modulo da OpenAI da aula pelo Claude.

**Acao concreta sugerida:**
- [ ] No fluxo do bot, adicionar node de normalizacao (Edit Fields manual mapping) mapeando nome, numero, mensagem, is group logo apos o webhook da Evolution
- [ ] Reaproveitar a expressao de split no @ para gravar o numero limpo (indice [0]) usado nas respostas
- [ ] Inverter a logica do IF para atender is group true (grupos de alunos), nao false
- [ ] Adicionar guarda para descartar eventos de grupo sem texto (reacoes) antes de chamar o Claude
- [ ] Confirmar que o passo de parsing JSON pode ser pulado por usarmos Evolution
