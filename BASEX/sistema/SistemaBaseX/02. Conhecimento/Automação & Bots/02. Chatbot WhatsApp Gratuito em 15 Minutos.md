# Como criar um chatbot para whatsapp GRATUITO (Em 15 minutos)

> Tutorial passo a passo de instalação local de um chatbot de WhatsApp gratuito baseado em script Node.js, com resposta automática por palavra-chave e conexão via QR Code. Vale absorver como referência de arquitetura no-code/low-cost antes de comparar com a stack robusta do bot BaseX.

**Canal:** [Jardel Bento]()  · **Duracao:** 00:15:39 · **Publicado:** 2024-08-15 · [Assistir](https://www.youtube.com/watch?v=MdZFR2op_mg)

---

## 1. Tese central

É possível montar um chatbot funcional de WhatsApp gratuitamente, sem mensalidade e sem saber programar, instalando quatro ferramentas locais (VS Code, Git, Node.js v14 e dois arquivos prontos do bot) e editando um fluxo de mensagens já pré-configurado. O bot responde automaticamente a partir de palavras-chave e de um menu numérico, conectando-se ao WhatsApp por QR Code como um aparelho vinculado.

### 2.1 Stack de 4 passos (instalação local)

**O que e:** A sequência fixa de instalação que torna o bot operante na máquina do usuário.

**Como funciona:**
1. Baixar e instalar o Visual Studio Code (editor onde o fluxo é editado)
2. Baixar e instalar o Git ("JIT" na fala do autor), só clicando Next até o fim
3. Baixar e instalar o Node.js na versão 14 (especificamente 14.21.3)
4. Baixar os dois arquivos do bot (chatbot e package) e colá-los na pasta criada

**Quando aplicar:** Quando se quer um bot de atendimento simples, local, sem custo de plataforma.

**Quando NAO aplicar:** Quando o autor não diz. Não aplicável — o vídeo não discute limites da stack.

> "Primeiro a gente vai fazer o download do Visual Studio Code... Agora a gente vai fazer o download aqui do segundo passo do JIT... a gente vai fazer o download do node... da versão 14... Baixar esses arquivos aqui. São dois arquivos do chatbot."
> — [00:00:27]

### 2.2 Fluxo de resposta por palavra-chave + menu numérico

**O que e:** A lógica de atendimento: gatilhos de ativação por palavra, seguidos de um menu de opções numeradas, cada número com sua resposta.

**Como funciona:**
1. Palavras-chave de ativação disparam o robô (ex: "bom dia", "quero saber", "test") separadas por barra reta `|`
2. Ao ativar, o bot puxa o nome do contato do WhatsApp e envia a mensagem de boas-vindas com o menu (1 Como funciona, 2 Valores dos planos, etc.)
3. Cada número digitado pelo cliente devolve a resposta correspondente já configurada
4. `delay` (em milissegundos) e "simulando digitação" dão cadência humana entre mensagens

**Quando aplicar:** Atendimento com respostas previsíveis e opções fechadas (FAQ, planos, catálogo).

**Quando NAO aplicar:** Não aplicável — o vídeo não trata de casos fora do menu fixo (não há IA/linguagem natural aberta).

> "Se a pessoa vier no seu WhatsApp e digitar bom dia, o nosso WhatsApp vai mandar essas mensagens que estão configuradas aqui... Se você quiser adicionar mais palavras, é só adicionar essa barra reta aqui, desse jeito aqui, e colocar por exemplo test."

## 3. Conceitos-chave

| Conceito | Definicao | Aplicacao pratica | Timestamp |
|----------|-----------|-------------------|-----------|
| Palavras-chave de ativação | Termos que disparam o robô, separados por `\|` | Editar a linha de gatilhos para captar variações da mensagem do cliente | [07:38] |
| Barra reta `\|` | Separador que adiciona/remove palavras de ativação (funciona como "ou") | Acrescentar barras para mais gatilhos, excluir barra+palavra para menos | [08:15] |
| delay | Pausa entre mensagens medida em milissegundos | Delay de 3s e de 5s entre blocos; excluir o último delay se não há mensagem depois | [08:37] |
| Simulando digitação | Comando que mostra "digitando..." antes de enviar | Deixa a resposta com aparência humana | [08:39] |
| Pegando contato | Puxa o nome cadastrado do contato no WhatsApp | "Olá {nome do contato}" personaliza a saudação | [08:46] |
| Bolinha branca | Indicador de alteração não salva no VS Code | Salvar com Ctrl+S ou File > Save para a mudança valer no WhatsApp | [09:55] |
| Comentário `//` | Texto entre duas barras é apenas comentário, não roda | Anotar sem afetar o fluxo | [09:22] |

## 4. Heuristicas e regras

Regras-de-bolso, atalhos mentais, principios que o autor enfatiza:

- **Sempre abrir o VS Code como administrador** — botão direito, "Executar como administrador", para não dar erros [00:10:19]
- **Só edite o que está entre aspas** — o conteúdo entre aspas é a mensagem editável; o resto (comandos, comentários com `//`) não se mexe [00:09:20]
- **Salve sempre que aparecer a bolinha branca** — sem salvar (Ctrl+S), a alteração não surte efeito no WhatsApp [00:09:56]
- **Teste sempre a partir de OUTRO WhatsApp** — o número conectado ao QR Code não consegue testar a si mesmo [00:13:06]
- **Se aparecerem vários QR Codes, o válido é o último de baixo** — múltiplos códigos significam que você demorou a conectar [00:12:35]
- **Não pular etapas na instalação** — pular passo gera erro; o autor faz tudo sem pular para evitar falha [00:04:03]
- **Node.js tem que ser a versão 14** — o autor escolhe explicitamente a 14.21.3, não a mais recente [00:04:23]

## 8. Aplicacao no nosso contexto

> Esta secao conecta o conhecimento absorvido com o projeto do bot BaseX (WhatsApp nos grupos de alunos da mentoria de dropshipping; stack Evolution API + n8n + Claude, respondendo dúvidas com o conhecimento do curso + relatórios de gestão semanais).

**O que isso muda na nossa operacao:**
Este vídeo é o extremo oposto low-cost do que o bot BaseX faz, e serve de contraste útil. A abordagem do Jardel conecta o WhatsApp via QR Code (aparelho vinculado) rodando um script Node.js local com resposta por palavra-chave e menu numérico fixo, sem IA. O bot BaseX resolve os mesmos primitivos (conexão ao WhatsApp, roteamento de mensagem, cadência humana com delay/"digitando") de forma muito mais robusta e escalável: Evolution API no lugar do script cru e da conexão frágil por QR (menos risco de queda/bloqueio, multi-instância), n8n para orquestrar o fluxo no lugar de editar um `chatbot.js` à mão, e Claude para responder em linguagem natural com o conhecimento do curso, em vez de um menu 1-2-3-4-5 engessado. Dois aprendizados aproveitáveis mesmo com stack superior: (1) o padrão de simular "digitando" + delay para a resposta parecer humana nos grupos de alunos; (2) o guard-rail de personalização (puxar nome do contato) — e o bug do "nome colado" é um lembrete de testar formatação de variáveis antes de subir. O que NÃO se copia daqui: conexão por QR Code raw e roteamento só por keyword, que não sustentam volume de grupos nem resposta contextual com o material da mentoria.

**Acao concreta sugerida:**
- [ ] Garantir que o bot BaseX use delay + indicador "digitando" no Evolution API para respostas nos grupos parecerem humanas
- [ ] Validar formatação de variáveis dinâmicas (nome do aluno, dados do relatório) antes do deploy, evitando o bug de "texto colado" mostrado no vídeo
- [ ] Documentar por que a stack Evolution API + n8n + Claude é preferível ao script Node + QR Code para o caso de uso de grupos de mentoria (robustez, escala, resposta em linguagem natural)
