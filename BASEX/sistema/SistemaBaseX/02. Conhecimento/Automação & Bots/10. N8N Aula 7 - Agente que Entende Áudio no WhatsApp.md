# Como criar um Agente N8N que entende Áudio no WhatsApp (Aula 7)

> Aula prática que implementa a transcrição de áudio dentro de um chatbot de WhatsApp no n8n, roteando cada tipo de mensagem (áudio, imagem, documento, texto) por um Switch e convertendo o áudio recebido em texto via OpenAI Transcribe.

**Canal:** [Rhavi Criador Digital](https://criador.digital)  · **Duracao:** 00:14:04 · **Publicado:** 2025-04-08 · [Assistir](https://www.youtube.com/watch?v=aUyM997-laA)

## 1. Tese central

O ponto de virada de um chatbot de WhatsApp "quase pronto" é ele entender áudio, porque o usuário final manda áudio o tempo todo. A aula mostra o caminho completo: o áudio chega no webhook da Evolution API como um código base64, é roteado por um Switch conforme o tipo de mensagem, convertido de base64 para arquivo de áudio (OGG) e transcrito para texto pelo nó Transcribe da OpenAI, virando input que o agente responde.

> "Para mim, quando a gente coloca o áudio, ele já está no primeiro passo de estar quase pronto."
> — [00:00:16]

## 2. Frameworks e modelos mentais

> Cada framework recebe nome, explicacao, quando aplicar e citacao verbatim com timestamp.

### 2.1 Roteamento por Switch (multi-tipo de mensagem)

**O que e:** Um nó Switch funciona como um `if` de várias saídas, cada uma testando um tipo diferente de mensagem que chega no webhook.

**Como funciona:**
1. Recebe o payload do webhook da Evolution API (contém tudo em `body`).
2. Para cada saída, testa se um objeto específico existe dentro de `message` (áudio, imagem, documento) ou se um campo string é igual a um valor (`conversation` para texto normal).
3. Manda a mensagem pela saída correspondente; o que não casa cai no fallback (extra output).

**Quando aplicar:** Sempre que o bot precisar tratar mais de um tipo de mídia (áudio, imagem, PDF, texto) de forma diferente.

**Quando NAO aplicar:** Se o bot só lida com texto puro, um Switch é overhead desnecessário.

> "O switch, ele é tipo um if, só que com várias saídas, né? O if, ele só tem duas saídas. O switch, a gente pode colocar o tanto que a gente quiser."
> — [00:02:28]

### 2.2 Pipeline base64 → arquivo → texto

**O que e:** A sequência de três passos que transforma o código base64 do áudio em texto legível pelo agente.

**Como funciona:**
1. **Edit fields (Data Transformation, antigo Set):** extrai o campo `base64` do payload e o deixa pronto para o próximo nó.
2. **Convert to File (Move base64 string to file):** converte o base64 em arquivo binário de áudio, definindo `fileName` (ex: audio) e `mimeType` (`audio/ogg`).
3. **OpenAI Transcribe (Transcribe Recording):** recebe o arquivo binário e devolve o texto transcrito.

**Quando aplicar:** Toda vez que uma API de WhatsApp entrega mídia como base64 e você precisa do conteúdo em texto.

**Quando NAO aplicar:** Se a API já entrega URL de mídia pronta para download, o passo de conversão base64 muda.

> "Isso aqui é um código que representa o áudio, tá? E a gente vai transformar esse código aqui em um arquivo de áudio."

## 4. Heuristicas e regras

Regras-de-bolso, atalhos mentais, principios que o autor enfatiza:

- **É sempre bom testar** — mesmo supondo que você sabe como a mídia chega, mande um exemplo real (áudio, imagem, PDF) e olhe o webhook antes de codar o roteamento [00:04:04]
- **Pin no webhook para não reenviar** — aperte P sobre o nó do webhook para fixar o dado e reutilizar em vários testes, sem ficar mandando áudio do celular toda hora [00:01:36]
- **Testa objeto por "exists", string por "is equal"** — tipos de mídia (audioMessage, imageMessage, documentMessage) são objetos e se testam por existência; texto normal é string `conversation` e se testa por igualdade [00:07:05]
- **Puxe o dado da normalização, não do webhook cru** — assim, se trocar de API de WhatsApp, o nome do campo permanece padronizado e o fluxo não quebra [00:09:16]
- **O n8n usa por padrão a saída do nó anterior** — para usar arquivo de outro nó, é preciso puxar via expressão explicitamente [00:11:37]
- **Prefira o nó pronto ao API call** — o Transcribe da OpenAI resolve direto; o da Groq exigiria chamada de API e é mais complicado [00:11:13]

## 8. Aplicacao no nosso contexto

> Esta secao conecta o conhecimento absorvido com o que ja existe no vault (BaseX, bot de WhatsApp de alunos).

**O que isso muda na nossa operacao:**
O bot BaseX vive nos grupos de WhatsApp dos alunos (Evolution API + n8n + Claude) tratando dúvidas e gestão. Alunos mandam áudio o tempo todo no grupo, então transcrever áudio é requisito direto, não luxo. Esta aula entrega o padrão exato que o nosso fluxo pode replicar:

- **Serviço de transcrição:** OpenAI Transcribe (Whisper) via nó nativo do n8n. Alternativa citada: Groq (via API call, mais complexo).
- **Como o áudio chega:** a Evolution API entrega o áudio como base64 no webhook, em `body.data.message.base64`.
- **Node do pipeline:** Webhook (Evolution) → Switch (roteia por `audioMessage`/`imageMessage`/`documentMessage`/`conversation`/fallback) → Edit fields (extrai base64) → Convert to File / "Move base64 string to file" (gera OGG, mimeType `audio/ogg`) → OpenAI Transcribe → texto vira input do agente Claude → resposta no grupo.
- **Formato de áudio:** OGG (padrão do WhatsApp/Evolution), mimeType `audio/ogg`.
- **Boa prática para o nosso bot:** puxar o base64 do nó de normalização, não do webhook cru, para não quebrar caso a API mude.

**Acao concreta sugerida:**
- [ ] Adicionar um branch de áudio no fluxo n8n do bot BaseX seguindo Webhook → Switch → Edit fields → Convert to File → Transcribe
- [ ] Definir se a transcrição usa OpenAI (nó pronto) ou Groq (mais barato, exige API call) e medir custo por minuto de áudio
- [ ] Testar com áudios reais de aluno (sotaques, ruído de fundo, áudio longo) antes de subir em produção
- [ ] Validar o mimeType do áudio que a nossa Evolution entrega (confirmar `audio/ogg`)
